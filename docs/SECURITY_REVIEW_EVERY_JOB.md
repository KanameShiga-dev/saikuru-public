# 依頼ごとのセキュリティレビュー（情報漏洩の確認を含む）（2026-10-06）

利用者の指示により、采来の全依頼で共通Agent `common-security-reviewer` によるセキュリティレビューを行うようにした。

## 変更

- 設定 `security_review`：`always`（既定・全依頼でレビュー）／`planner`（従来どおり計画担当の `security_review_required` 判定時のみ）。`data/config.json` は `always`。
- レビューの観点に情報漏洩を追加：依頼範囲外への通信・送信・公開、プロジェクト外や認証情報の読み取り、検索語や成果物への社内情報・個人情報・認証情報の混入、外部公開されるポート・設定の追加。
- レビュー担当のプロンプトに、統括がローカルで作る証拠を添付（`team_security_audit.py`）：
  - この依頼の操作記録（実装担当のコマンド本文 `operation_bash`、自動承認、Web検索の許可・停止、編集）。
  - 依頼開始後に作成・変更されたファイルの機械チェック（認証情報らしき文字列、メール、電話、社内IP・ホスト、`data/websearch-policy.json` の登録語）。値は伏せ、ファイル・行・種類のみ。Word/Excelは文字を抽出して確認、PDF等は対象外。
- 実装担当のコマンドを全てイベント `operation_bash` に記録（自動承認時も残るように）。
- 指摘（needs_changes）は既存のレビューと同じく自動で修正担当を作成（最大 `max_repairs` 回）。上限超過は停止して利用者判断。

## 確認

過去の依頼（05）の記録で証拠の生成、仕込んだ秘密情報・メール・社内IPの検出、依頼開始前のファイルを対象外にすることを確認。実モデルでの依頼一巡・テストスイートは未実行。依頼ごとにレビュー担当（opus）の実行が1回増える。
