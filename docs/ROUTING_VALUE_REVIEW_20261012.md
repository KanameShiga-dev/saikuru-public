# 采来の実行経路と振り分け基準（2026-10-12）

状態：設計に基づく評価専用の軽い経路を試作。稼働サービスの実行経路・設定は変更していない。隔離比較は `ROUTING_COMPARISON_RESULTS_20261012.md` を参照。

## 目的と判断単位

指定条件を満たして通常受領された依頼1件あたりの総AIトークンを減らす。品質、安全、権限、必須検証、利用者の受領を先に満たす。条件付き受領（`accepted_with_pending_checks`）は通常受領と分ける。人の実作業時間と介入回数は別に記録する。

振り分けの単位は依頼全体。担当の途中で安易に経路を切り替えて変更や検証を重複させない。

## 現行コードとの対応

| 対象 | 現行動作 | 設計上の扱い |
| --- | --- | --- |
| `team_engine.create_job` | 全依頼に計画タスクを作る | 采来の通常経路として維持。軽い経路の試作時だけ別の入口を追加する |
| `team_limited_routing.classify_intake` | 受付時の分類を計画担当の参考として記録する | 実行の許可・レビュー省略・経路決定に使わない。過去の受付分類12/15一致だけでは自動振り分けできない |
| `_queue_reviews` | 通常レビューを追加。既定の`security_review=always`ではセキュリティレビューも追加 | 軽い経路でも両レビューを維持する。レビューを減らす判断は別課題で効果と安全性を確認した後に行う |
| 受領判定 | 未確認事項があれば`accepted_with_pending_checks` | 経路によらず同じ承認・受領画面と区別を使う |

## 三つの使い分け

| 経路 | 適する依頼 | 動作・制約 |
| --- | --- | --- |
| 直接CLI | 範囲、成果物、合格条件が明確で、単一担当で終えられ、采来の中断復旧・引き継ぎを必要としない依頼 | 采来の外で利用者が選ぶ比較対象。采来が外部CLIへ自動転送したり、采来の承認記録が残ると表示したりしない。適用先のCLIの権限・承認ルールに従う |
| 采来・軽い経路（試作案） | 新規の単一制作依頼で、対象と合格条件が明記され、調査・担当交代・計画判断が要らない場合 | 計画用AI呼び出しだけを省き、制作1担当→通常レビュー→既定のセキュリティレビュー→利用者受領へ進む。采来の承認、操作記録、成果物確認、修正上限、未確認事項の扱いは同じ |
| 采来・通常経路 | 複数工程、担当交代、要件の整理、資料・添付、未知の依存関係、判断待ち、リスクがある場合 | 現行の計画→担当作業→通常・セキュリティレビュー→利用者受領を使う。不明点はこの経路へ戻す |

## 軽い経路の初期対象

初期試作は、隔離された架空課題で明示的に選ばれた新規依頼に限る。自動分類だけでは選ばない。開始条件をすべて満たす必要がある。

1. `auto_execute=true`で、依頼者が対象プロジェクト、作る／直す成果物、変更してよい範囲、独立に確認できる合格条件を指定している。
2. 制作担当が1人で完結でき、調査・設計判断・担当交代・既存の未解決引き継ぎを必要としない。
3. 認証、権限、外部通信・公開、削除、重要データの移動、機密情報、実業務の添付、資料形式固有の制作経路を含まない。
4. `security_review=always`で、既存の承認・ファイル範囲・安全ガードをそのまま適用できる。設定が`planner`なら、計画担当の判定を省く軽い経路は使わない。分類できないものと条件が一つでも不明なものは通常経路を使う。

初期対象を満たしても、実施中に範囲の拡大や不明点が出れば担当を停止して利用者へ表示する。編集後に計画担当を自動挿入して同じ作業を再実行しない。継続する場合は、残った作業、既存の変更、未確認事項を確認してから利用者が判断する。

## 軽い経路の実装に必要な変更

これは実装時の境界であり、本書の作成で実装済みとは扱わない。

- `server.py`と依頼画面：経路の明示選択と、合格条件・許可範囲の入力／確認。既定は通常経路。受付分類のヒントだけで軽い経路へ切り替えない。
- `team_engine.py`：新規依頼の軽い経路だけ、依頼を`running`で保存し、計画タスクの代わりに制作タスクを作成して、既存の通常・セキュリティレビューを後続に接続する。計画承認を経ないため、初期対象は明示的な自動実行指定に限定する。操作承認・修正・受領の状態遷移を共用する。
- 保存記録：依頼ごとに要求経路、実効経路、選択根拠、途中停止／切替の理由を残す。過去依頼の経路を推定・書換えしない。
- 集計：経路別の全試行トークン、通常受領率、条件付き受領、停止、修正、人の介入を分ける。利用量の欠損を0としない。

## 採用前の確認

軽い経路を通常の依頼で使う前に、同じ架空課題、モデル、effort、道具、安全条件で直接CLI・軽い経路・通常経路を比較する。品質・権限・秘密情報・完了ゲートが同等で、総トークンと人の介入に実用上の利点がある依頼種別だけへ適用する。レビューを減らす比較はこの段階の対象に含めず、別の判断として扱う。

特に、計画を省いた結果として合格条件の欠落、余計な編集、レビューからの修正増、条件付き受領の増加があれば、軽い経路の利点として数えない。
