# 参考添付の許可とプロンプトインジェクションの拒否

2026-10-04、利用者の明示した許可形式と「疑いがあれば拒否」の条件を実装。新規依頼と台帳相談に共通適用。公開対象とし、実行確認の限界を下記に記録。

## 許可形式と扱い
|形式|AIへ渡す内容|
|---|---|
|静止PNG / JPEG / WebP|画素をデコード、メタデータを検査し除去して正規化したPNG。日本語・英語のローカルOCRを検査|
|PDF|全文字抽出と全ページの描画・OCRを検査した抽出文字。原本をAIへ渡さない|
|DOCX / XLSX / PPTX|全XMLの本文・コメント・ノート・隠しセル・代替文字・参照先と、同梱画像OCRを検査した文字。計算・マクロ実行・外部参照の取得はしない|
|TXT / Markdown / LOG / CSV / JSON / YAML / XML / TOML / INI等|読み取り専用の文字。UTF-8（BOM可）、BOM付きUTF-16、CP932。JSONは構文も確認|
|一般的なソースコード（PY / JS / TS / CS / JAVA / C / CPP / GO / RS / HTML / CSS / SQL / SH / PS1等）|コードを実行・importせず文字として検査。作業範囲や実行承認として扱わない|

拡張子の正本はattachment_extract.pyのALLOWED。EXE/DLL・旧Office・マクロ付きOffice・パスワード付きファイル・一般ZIP等は対象外。Office内部のマクロ、ActiveX、埋め込みファイル、外部データ接続、実行系数式、検査できない二進数部品も拒否。PDFの実行アクション・埋め込みファイル・フォーム実行等も拒否。通常の参照ハイパーリンクは文字として検査するだけで取得しない。

文書の図表・レイアウト・計算結果は再現しない。原本を編集する機能ではなく、作業のための参考添付。画像の場合だけ正規化した画素もAIへ渡す。

## 拒否処理
- 添付名と全文を日本語／英語の決定的ルールで検査。上位指示の無視、ロール偽装、承認の迂回、秘密情報の取得・送信、利用者への隠蔽、結果の偽装を疑う場合は拒否する。
- Unicode正規化、不可視文字、よく使われる見かけの似た文字、HTML実体、URLエンコード、Unicodeエスケープ、一定範囲のBase64／16進文字列も確認。区切り文字で分割した既知の指示も確認する。
- 画像は全解像度の画素を重なり付きの領域に分けてOCR。空の認識結果だけで「文字がない」と断定しない。OCR処理の成功は検出完全性の保証ではない。
- 拒否ファイルの原本・抽出文字は永続保存せず、外部AIへ送らない。処理用の一時ファイルは終了時に片付ける。拒否理由には資料本文や秘密値の抜粋を載せない。
- 全文の抽出・OCR・構造検査ができない場合、依存不足、破損、暗号化、処理上限、時間切れ、検査中の競合は拒否する。勝手な切り詰めやAIでの代替検査はしない。
- 複数ファイルを合わせた内容も、相談への追加・依頼作成・各AI担当への送信前に検査。導入前の保存画像も初回再利用時に検査する。保管した原本と検査結果のハッシュ、検査ルールの版を確認し、不一致は拒否する。
- 検査を通った文書はJSONのuntrusted_reference_textとしてAIへ渡し、画像・文書から実行範囲や承認を変更しないネイティブ指示を継続する。添付内のソースコードは実行しない。

正当な仕様書・ソースコードで攻撃例を説明している場合も保守的に拒否されることがある。疑わしい記述を除いて再添付する。利用者が拒否を上書きするボタンは設けていない。

## 上限と保存
依頼／相談1件4ファイル、各5MB、合計15MB。抽出内容は添付セット全体15万文字以内。PDF20ページ以内、OCR40領域以内、各画像8192px・1600万画素以内、Office展開30MB・1500部品以内。1ファイルの検査120秒以内。保存容量は原本と検査結果を合わせて512MB以内。

`data/attachments/<UUID>.bin`に許可した原本、同じIDの`.safe.json`に検査済み文字と正規化画像を保存。team.sqlite3のattachmentオブジェクトにguard_version・prepared_sha256・kind・preview_mimeを追加。既存DBの破壊的移行はない。GETのプレビューは原本ではなく検査済み画像／プレーンテキストだけ。認証済みのローカル利用者は既存と同じ権限で参照できる。個人別権限、保存画像の削除画面は未実装。バックアップにはDBとdata/attachmentsの両方が必要。

認証・同一オリジン・POSTのX-Agent-Team-UI・既存の承認条件を維持。画像のローカルプレビューのためCSPのimg-srcだけselfとblobに限定して許可。外部の画像・スクリプトや文書iframeを許可しない。

## 解析環境と再現
本体Pythonから別プロセスのattachment_extract.pyを呼ぶ。OSのユーザー権限を分離したサンドボックスではなく、解析内容の実行やネットワーク参照を行わない処理。1件ずつ検査し、競合は拒否する。

任意の専用Pythonを`data/attachment-runtime.json`のpythonへ絶対パスで指定できる。未設定なら本体Pythonを使用。Pillow・pypdf・pypdfium2とWindowsの日本語／英語OCRが必要。今回、既にあるローカル同梱環境を登録し、新しいライブラリのインストールや更新は行っていない。再現用の版はrequirements-attachments.txt。必要な解析環境がなければ画像／PDF等を拒否し、検査を省略しない。

Windows PowerShell 5.1用OCRヘルパーはUTF-8 BOM。固定のAPI呼び出しとJSONだけを使用し、資料本文をPowerShellのコードへ展開しない。

## 確認と限界
構文（Python7ファイル・JS3ファイル・PowerShellヘルパー）・許可拡張子45種類の前後一致・HTMLのID重複なし・入力から保存／AI送信までの処理経路を読み取り確認。処理中の作業・相談がない状態で正常再起動し、新規依頼・台帳・添付JSがディスクと同じ内容で配信されることを確認。日本語と英語のWindows OCR言語が登録され、利用する解析ライブラリが既存の環境にあることを確認。

今回はテスト追加・テストスイート・検査用の添付送信・実モデル呼び出しは行っていない。実際のPDF/Office/OCR、拒否・誤検知、画像貼り付け、AIまでの一巡とスマホ実機は未確認。

既知のパターン検査とOCRには見逃しがある。新しい言い回し、読めない／別言語の文字、画像内の巧妙な偽装などを完全に検出する保証はない。検査通過を安全の保証として表示しない。形式拒否・全文検査・参考資料の分離・既存の権限／承認条件を合わせて運用する。

参考：[OWASP Prompt Injection Prevention](https://cheatsheetseries.owasp.org/cheatsheets/LLM_Prompt_Injection_Prevention_Cheat_Sheet.html)、[Microsoft Windows OCR API](https://learn.microsoft.com/en-us/uwp/api/windows.media.ocr.ocrengine.recognizeasync)。

## 戻し方
変更前のソース／マニュアルをローカルでバックアップしています。正常停止して必要なソースを戻し、再起動する。新しい添付や依頼を失わないようDBは巻き戻さない。新たに許可した文書を旧画像のみの版へ戻す場合、その文書をAIへ送信しない状態を保ち、文書添付のある依頼を再開しない。通常は画像版に戻すより、添付送信を停止したうえで検査処理を修正する。

## 導入例
専用Pythonへ `python -m pip install -r requirements-attachments.txt` で依存を準備します。Windowsに日本語・英語OCRが必要です。インストールは今回の公開作業では実施していません。

`data/attachment-runtime.json` の設定例（実際の専用Pythonのパスへ置換）：
```json
{"python":"C:/Python/python.exe"}
```
個人環境の設定ファイル・添付・DBはGitへ登録しません。環境が不足すると拒否理由を表示します。テキストで必要な要点を入力する方法も利用できます。
