# 参考PDFのデザイン学習と統一デザインの反映（2026-10-07）

参考PDFから「デザインプロファイル」（色・書体・文字サイズ・行間・用紙・余白）を取り出し、PowerPoint・PDF・動画・Word・HTML の成果物に同じデザインを当てる。采来（サイクル）とデスクトップアプリの Claude Code の両方で使える。

## 決めたこと（利用者：2026-10-07）
- 反映先：PowerPoint（PPTX）、Word・PDF・HTML。Excel と Claude の Artifact は対象外。
- 使う場所：采来とデスクトップの両方。
- PDF解析ライブラリ pypdf 6.19.0・pypdfium2 5.14.0 を導入（一時的なスケジュールタスクで `pip install --user`。利用者承認済み）。

## 采来での使い方
1. 参考PDFを読み取り元フォルダか保存先フォルダに置く。
2. 台帳 → 相談 → 資料作成。依頼文に「参考PDF（ファイル名）のデザインに合わせる」と書き、形式に PPTX・PDF・MP4・Word・HTML のどれかを選ぶ。
3. 制作担当が `learn_design` を使い、保存先の `design\<名前>.design.json` と `design\<名前>.design.md`（日本語の要約）を作る。
4. 制作担当は、成果物を作る道具に `design_profile` を指定する。
   - `generate_media`（PPTX・PDF・MP4）：色の役割（アクセント、見出し、本文、背景、面、補足）と、見出し・本文の書体
   - `generate_office`（Word）：本文・見出し・注記のスタイル（書体、サイズ、色、行間）と表の色。新しいファイルなら用紙と余白も
   - `write_document`（HTML）：`<head>` にCSS（変数、`@page`、見出し・表の規則）を入れる

## デスクトップでの使い方
スキル `pdf-design-learning`（`~\.claude\skills\pdf-design-learning\SKILL.md`、原本は `skills\pdf-design-learning\SKILL.md`）。
「このPDFのデザインに合わせて」のように頼むと読み込まれ、`design_profile.py` で学習してから反映する。

## 学習の中身（`design_profile.py`）
| 項目 | 取り方 |
|---|---|
| 文字サイズ | 文字の量が最も多いサイズを本文とする。大きいほうから順にタイトル・見出し1・見出し2、小さいものを注記とする |
| 書体 | 本文サイズと見出しサイズで、最も多く使われた書体名。このPCにある近い書体に置き換える（例：Noto Sans JP → Yu Gothic） |
| 文字色 | 描画命令の塗り色を、本文・見出しのそれぞれで文字数の重みを付けて集計する |
| 配色 | 最大8ページを小さい画像にして、背景・面・補足の色を取る。はっきりした色は、小さな線や記号も拾える方法で別に集計し、メイン・サブの色にする |
| 行間・余白 | 本文の行の間隔と、文字の位置の分布から推定する |
| 安全 | 読み取りのみで、PDFの中身は実行しない。50MBまで、パスワード付きは不可。プロファイルは使う前に形式を厳しく検査する（色は `#rrggbb`、書体名は英数字と空白だけ） |

## 追加：PPTX の中身の読み取り（2026-10-07、サンプル08の改善点1）
- サンプル08で、レビュー担当が PPTX の中身を読めず、毎回「未確認」で止まった。
- `read_document` で `.pptx` を読むと、次の情報を返すようにした（`document_tools.pptx_text`）。
  - スライドごとの文字（上から読む順）
  - 表（`[表 r行×c列]` と各行）、図の箱（`[図形]`）、発表者メモ
  - 枚数、各スライドの表・図形・画像の数
  - デザインの集計（書体、文字色、塗り、文字サイズ）。デザインプロファイルと照合できる
- 読み取る前に Office ファイルの安全確認（マクロ・外部リンク・埋め込みの拒否）を行う。描画も実行もしない。
- 配置の崩れ・はみ出し・読みやすさといった見た目は、引き続き画像での確認が必要。
- テスト：`test_document_read.py`。変更前のファイルは `data/backups/pptx-read-20261007/`。

## 追加：サブ色を差し色として使う（2026-10-07、サンプル08の改善点2）
- 参考PDFにあった2つ目の色（例：紺に対するオレンジ）を、PPTX と PDF・MP4 のページ画像で差し色に使う。
  - PPTX：表紙のタイトル下の線、章扉の番号下の線、本文スライドのタイトル下の短い線
  - PDF・MP4：タイトル下の短い線
- 使うのは、メインの色と色相が25度以上離れ、鮮やかさが十分な色だけ（`design_profile.slide_palette`）。メインの色から作った淡い色（同じ色相）は使わない。
- 表紙・章扉の濃い地の上では、見分けにくい色（明るさの比が1.5未満）なら従来の白い線のままにする。
- プロファイルを指定しない場合の見た目は変わらない。
- テスト：`test_design_profile.test_spot_colour_only_when_distinct`。変更前のファイルは `data/backups/pptx-secondary-20261007/`。

## 追加：内容の少ないスライドの組み方（2026-10-07、サンプル08の改善点3）
- 本文だけのページで、行が1〜4行（各40文字以内）、表・図・画像が無いものは、自動で次のように組む（`document_media_worker._sparse_lines`）。プロファイルの有無は問わない。
  - 1行：大きな一文（32pt・太字）をページ中央に置き、上に短い線を引く
  - 2〜4行：番号付きのカード（01・02…）を横に並べ、ページの縦中央に置く。カード上端の線は差し色（無ければメインの色）
- カードの文字サイズは、すべての項目が1行に収まるか、2行目が3文字以上になる最大のサイズ（24〜14pt）にそろえる（`_card_size`）。1文字だけ次の行に送られることを防ぐ。
- 行頭の「・」「-」などの記号は取り除く。表紙・章扉、行の多いページ、表・図・画像のあるページは従来どおり。
- PDF・MP4 のページ画像にも同じ組み方を入れた。
- テスト：`test_document_read.SparseLayoutTest`。変更前のファイルは `data/backups/pptx-sparse-20261007/`。
