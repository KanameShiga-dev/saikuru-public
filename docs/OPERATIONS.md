# 利用・保守手順

2026-09-27。初期版。二者連携の実運用は未確認。

## 起動・停止

Python 3.11以上（このPCでは3.14）。外部Pythonパッケージは不要。

```powershell
python -X utf8 C:\AI_Work\Projects\Operations\agent-team\manage.py start
python -X utf8 C:\AI_Work\Projects\Operations\agent-team\manage.py status
python -X utf8 C:\AI_Work\Projects\Operations\agent-team\manage.py stop
```

画面: <http://127.0.0.1:8787>

PC再起動時の自動起動は登録していない。同梱PowerShellスクリプトは補助。
このPCではスクリプト実行ポリシーにより起動が拒否されたため、Pythonランチャーを確認済み経路とする。実行ポリシー変更は不要。

## Claude Codeのログイン

Claude Desktopが使えていても、アプリ外から起動したCLIで認証が使えるとは限らない。
このPCでは `Not logged in` と `auth status --json` の loggedIn=false を確認した。

利用者が次をターミナルで実行し、ブラウザ上の本人確認を完了する。

```powershell
python -X utf8 C:\AI_Work\Projects\Operations\agent-team\manage.py login-claude
```

`auth login --claudeai` を使用する。ConsoleのAPI従量課金への切替や、認証情報のコピーは行わない。
ログイン後はサービスを停止・再起動して画面の状態を更新し、次の接続確認を行う。

```powershell
python -X utf8 C:\AI_Work\Projects\Operations\agent-team\probe_live.py claude
```

プローブも実際のCLI利用枠を消費する。合成入力のみを送り、ツール操作は拒否する。

## 最初の依頼

初期登録は `sample-project` のみ。最初は次のような小さな依頼を試す。

「Pythonの加算関数をcalculator.pyに作り、unittestで検証し、別担当がレビューする。」

画面の「依頼を追加」に目的と完了条件を入力する。
自動実行を選ぶと、計画後の作業とレビューを自動で開始する。選ばなければ計画承認を待つ。
担当の選択と引き継ぎは自動。別AIの既存Desktopチャットを直接操作する方式ではなく、新しいCLI実行をタスク単位で開始する。

計画は1〜6件、異なるプロジェクトの同時実行は最大2件、自動修正は最大2回。
実装とレビューを別の提供元にする初期設定だが、品質の優劣を断定した固定分担ではない。
失敗時の無条件なモデル切替や連続再試行は行わない。

「担当作業終了」はAIの処理終了を示す。利用者が最終成果を受け入れるまで、依頼は確認済みにならない。
操作承認は15分、タスクは30分を上限とし、承認待ちもタスク時間に含む。
中止しても、それまでのファイル編集や外部作用は取り消されない。

実際の編集、コマンド承認、拒否、取消、相互引き継ぎを確認してから、「チーム設定」で実プロジェクトを登録する。

## モデルが変わるとき

### Codex CLIの更新

Agent Teamは起動時と24時間ごとにnpm版Codex CLIの公開版を確認する。チーム設定に現行版、公開版、確認日時を表示し、新しい版があればCodex欄にも表示する。確認はCLIの利用枠を消費しない。画面の「今すぐ確認」で再取得できる。

「CLIを更新」を押した場合のみ、表示された版を `npm install -g @openai/codex@<version>` で導入する。実行中の作業、アーカイブ、移動がある場合は開始しない。更新中は新規着手を一時停止し、終了時に元の停止状態へ戻す。成功後は版数を確認し、接続状態とモデル一覧のキャッシュを更新し、Codexの利用枠を直ちに再取得する。失敗して導入版が変わった場合は元の版への復旧を試みる。復旧できない場合は画面に明示する。

これはWindowsユーザーのグローバルnpm版に作用するため、Agent Team以外で同じCLIを使う場合にも影響する。Codexデスクトップアプリ同梱のCLIは別管理。新しいモデルが一覧に出るかは更新後のCLIとアカウントで再確認する。

手動復旧が必要なら、作業が止まっていることを確認し、更新前の版を指定して `npm install -g @openai/codex@<version>` を実行し、Agent Teamを再起動する。

### Claude Code CLIの更新

Agent Teamは起動時と24時間ごとに、使用中のClaude Code CLIの版数とnpmの公開版を比較する。npmの公開版は更新候補の目安であり、CLIの公式更新コマンドが実際に導入する版を保証するものではない。

「Claude Code CLIを更新」を押した場合のみ、現在検出しているCLIで公式の `claude update` を実行する。実行中の作業がある場合は開始せず、更新中の新規着手を止める。更新後はAgent Teamが実際に使用するCLIを再検出し、以前より新しい版になったことを確認し、Claudeの利用枠を直ちに再取得する。版数が変わらない場合は、起動用パスまたは導入方式の問題として表示する。Claude Desktop本体の更新はこの操作に含まない。

利用枠の再取得が認証や取得回数制限などで失敗した場合、CLIの更新成功とは分けて画面に表示する。以前の利用枠は最新値として扱わない。認証情報や取得エラーの生データは記録しない。

このPCでは2026-09-30時点で、Claude Desktop配下のネイティブ版CLIを検出している。`claude doctor` は自動更新有効と報告した一方、独立した起動用パスの欠落も警告した。更新が失敗した場合は残っている旧版の利用可否を確認し、必要なら公式の導入手順で起動用パスを修復する。Agent TeamはClaudeの設定やPATHを自動変更しない。

役割は計画・調査・実装・レビュー。モデル名は役割のプロファイルに保存する。
「チーム設定」で提供元・モデル名・推論量を変更でき、今後作成するタスクに適用する。
作成済みタスクは元のプロファイルを保持する。

新モデル名の保存は、利用権・互換性・品質の確認を意味しない。
変更前設定は `data/config-backup-*.json` に保存する。
接続、構造化出力、承認、編集、レビューのサンプル試験を行ってから継続利用する。
モデル別名が将来別のモデルを指す可能性にも注意する。Claudeの実接続イベントには返されたモデル名を表示する。

Codexの初期値は現行方針に沿ってSol・medium・Standard・Fast無効。
AstraとHighは初期版のワーカーでは禁止する。既存High証拠ゲートを迂回しない。
別提供元を追加する場合は、接続部と共通結果・承認契約の検証が必要。

## データと復旧

- `data/team.sqlite3`: 依頼・結果・承認・要約イベント。コードや個人の入力を含み得るので公開しない。
- `data/handoff.sqlite3`: モデル間の引き継ぎ履歴、現在の情報、矛盾の解消記録。作業内容や利用者の判断を含むため公開しない。
- `data/config.json`: この統括サービスだけの設定。
- `data/file-backups/`: 自動許可したClaudeファイル編集前のコピーとマニフェスト。
- `data/server.*.log`: 起動や異常の診断。通常のHTTPアクセスログは保存しない。
- `.test-output/`: 隔離した検証データ。通常運用のDBと分ける。

DBバックアップは画面のボタンから作成する。タスクDBと引き継ぎDBの2ファイルが保存される。
復元時はサービスを停止し、現在のdata全体を退避してから、対になったバックアップDBを別データフォルダの `team.sqlite3` と `handoff.sqlite3` として復元する。
`server.py --data <復元先> --port <空きポート>` で確認してから採用する。復元は自動実行しない。
DB復元ではプロジェクトの編集は戻らない。ファイル退避やGit差分を確認して個別に戻す。

初期版の停止だけなら `manage.py stop` で十分。アンインストール時も先に停止しdataを保管する。
グローバル方針や既存プロジェクトを今回変更していないため、その復元操作は不要。
