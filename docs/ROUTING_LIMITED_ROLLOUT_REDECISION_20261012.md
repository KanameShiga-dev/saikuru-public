# 采来の軽い経路：限定導入の再判断（2026-10-12）

結論：**今回は限定導入しない。** 評価専用の明示選択だけを残し、通常サービスの既定経路、セキュリティレビュー、承認、データは変更しない。判断材料は[初回比較](ROUTING_COMPARISON_RESULTS_20261012.md)と[追加評価](ROUTING_ADDITIONAL_EVALUATION_20261012.md)。

## 判断条件と観測

| 条件 | 観測 | 判定 |
| --- | --- | --- |
| 明確な単一ファイル修正で同等の独立採点と通常受領 | 算術課題3組と文字列課題2組で両経路とも合格。ただし受領は評価ランナーの代理操作 | 限定的に確認 |
| 同じ条件で全試行を含む費用改善 | 算術課題の軽い経路は32.8%、文字列課題では20.8%少ない取得済みトークン。直接CLIの認証失敗2回はusage不明 | 小課題では改善を観測。一般化不可 |
| 資料・複数工程など別種の仕事 | 資料作成は軽い経路の適用外。通常経路でも最終レビュー前に予算停止し、受領なし | 未確認 |
| レビューが実欠陥を防ぐ効果 | 資料作成で通常レビューが初回不備に `needs_changes` を返し、修正後の独立採点は合格。後続レビューは未完了 | 一例のみ |
| 実利用者の受領と負担 | 架空案件で本人が1項目の根拠を記録して条件付き受領。残る項目の再受領、実作業時間、操作負担は未確認 | 一部確認 |
| 安全性と回復可能性 | 評価は隔離した架空案件のみ。通常サービスでの長期観測、停止・再開、実際の回復は未実施 | 未確認 |

効率改善は、採点可能な小さなコード修正という狭い範囲で再現した。一方、通常サービスの利用者が必要とする受領・安全性・回復の条件は満たしたと判断できない。レビューや承認を外して差を拡大する変更はしない。課題8の測定枠は取得済み930,589/1,000,000トークンで、usage不明の直接CLI失敗2回がある。追加の実AI試行はこの枠では開始しない。

次回の導入判断をする場合は、代表的な別種の仕事を最後まで受領できること、実利用者の再受領と負担を確認できること、失敗・中止・不明利用量も含む費用の見通し、安全上の逸脱がないことを先に確認する。新たなAI費用が必要なら別途上限を決める。公開・push・通常サービス変更はこの判断に含まない。
