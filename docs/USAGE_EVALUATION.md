# 経験・Skill再利用の効果検証の手順（改修② Phase 2）

目的：経験DB・正式Skillの再利用で、**受け入れた成果物1件あたりのクラウドAI利用量**が減るかを、同じ品質条件で比べる。
この手順は第三者が同じ方法で再現できるように書く。結果は良くても悪くても記録する（15%削減は検証前の暫定目標で、実測ではない）。

## 1. 仕組み

| 機能 | 内容 |
|---|---|
| 検証モード | 「依頼を追加」の「効果検証（検証用の依頼だけ）」で A〜D を選ぶ。A＝経験なし・スキルなし／B＝経験のみ／C＝スキルのみ／D＝両方 |
| 切り替える範囲 | AIに渡す**再利用の文脈だけ**（`enterprise_experience`・`reviewed_project_skills`）。DBの経験・スキルは消さない。安全の指示・承認・利用者の判断・現在の事実・引き継ぎは変えない |
| 制約 | 検証用の課題であることの確認が必須。依頼時のスキル追加・「スキルを使わない」とは併用できない |
| 記録 | 試行ごとに `context_refs.evaluation_mode`、利用量（Phase 1 の計測） |
| 集計 | `python -X utf8 team_optimization_metrics.py` の `evaluation_modes`（モード別の依頼数・受入数・受入率・**受入1件あたりの入力・出力トークン**。失敗・再試行も含む） |

## 2. 文脈の予算（改修③）

| 設定（data/config.json の `context_budget`） | 動作 |
|---|---|
| なし／`{"mode": "shadow"}`（**既定**） | 選別を計算して記録するだけ。AIに渡す内容は変えない |
| `{"mode": "on", "reuse_chars": 8000}` | 再利用の文脈だけを予算内に絞る：依頼と関係の薄い経験は入れない、人が記録した経験を優先、予算を超えたスキルは要約＋SKILL.md の場所だけ（依頼時に追加したスキルは常に全文） |
| `{"mode": "off"}` | 従来どおり（記録もしない）。障害時の切り離し用 |

安全の指示・利用者の判断・承認条件・現在の事実は、予算の対象外（削らない）。
SHADOW の記録は `context_budget`（減らしていたら減った文字数・外れた経験の数）。**文字数でありトークンの実測ではない**。ON にするのは、SHADOW の記録と比較試験で品質が落ちないことを確認してから。

## 3. 比較試験の手順

1. **課題を用意する**：同程度の難しさの課題を3件以上。実業務のデータを含めない（`C:\Projects\samples` 等の検証用フォルダ）。各課題に受入条件を文書で決めておく。
2. **条件をそろえる**：モデル・推論設定（チーム設定）、采来の版（`saikuru_version`）、文脈の予算の設定を、試験の間は変えない。
3. **経験・スキルの下地**：B〜D で比べる対象の経験・スキルが、対象プロジェクトに登録済みであることを確認する（無いと A と差が出ない）。
4. **実行順を入れ替える**：課題ごとに A→B→C→D、次の課題は D→C→B→A のように順番を変え、慣れによる差を打ち消す。
5. **同じ受入条件で判定する**：受け入れ・差し戻しは課題ごとの受入条件だけで判断する。
6. **集計する**：`team_optimization_metrics.py` の `evaluation_modes` と、`--csv` の試行ごとの行を保存する。
7. **削減率**：（A の受入1件あたり利用量 − D の受入1件あたり利用量）÷ A の受入1件あたり利用量 × 100。失敗・時間切れ・品質未達の試行も含めた合計で計算し、成功した試行だけを選ばない。
8. **記録する**：課題・モード・順番・版・設定・結果・受入率・気づいた点を、良い結果も悪い結果も残す。
