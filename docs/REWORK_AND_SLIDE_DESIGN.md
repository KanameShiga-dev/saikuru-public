# 差し戻し（拒否理由）での作業再開とスライドのデザイン対応（2026-10-06）

## 差し戻しで作業を再開する

利用者の指示により、成果物の受け入れを「拒否」したときに理由・指摘が入力されていれば、依頼を止めずに次を自動で行う（`Engine.rework_from_rejection`）。

1. 修正担当（builder）「利用者の差し戻し指摘を反映する」を作成。指示に利用者の指摘をそのまま入れ、対応できない点は理由と代替案の報告を求める。資料作成では修正版を新しい名前で保存し最新版を明記させる。
2. 続けて通常レビューとセキュリティレビューを予約。指摘があれば既存どおり自動修正（最大 max_repairs 回）。
3. 依頼の状態を running に戻し、差し戻し回数（rework_count）とイベント `rework_requested` を記録。

理由なしの拒否は従来どおり停止。処理中の依頼・中止済みの依頼は差し戻し不可。停止中の依頼を理由付きで再開する API `/api/jobs/rework`（id, note）を追加。画面の受け入れ欄に動作の説明を表示。

## スライド（PPTX）のデザイン

`generate_media` のPPTXを、文字枠だけの白地から次へ拡張（`document_media_worker.build_pptx`）。PDF・MP4は表・図を文字で表示。

- 配色 `theme.accent`（#RRGGBB）、資料名 `document_title`（フッター）
- `layout`：cover（全面配色の表紙）／section（章扉。番号と見出し）／content（上部の色帯・見出しの印・フッターとページ番号）。1枚目の既定は cover。
- `table`：本物の表（1行目は配色の見出し、行の交互配色）。最大20行×8列。
- `diagram`：角丸の箱と矢印の図。type=flow（横）／stack（縦）、nodes 2〜8。
- `notes`：発表者メモ。
- ページに収まらない場合は「何枚目のどのページか」を返す（本文・表・図・画像の合計で判定）。上限は80ページ。

確認：試作5枚（表紙・章扉・流れ図・積み重ね図・表＋メモ）を生成し、PowerPointで画像に書き出して見た目を確認。PDFの生成、収まらないページと入力不正のエラーを確認。差し戻しは一時データで、修正担当→通常レビュー→セキュリティレビューの予約、running への復帰、理由なし・処理中の拒否を確認。実モデルでの一巡は、拒否されたPPTX依頼を `/api/jobs/rework` で再開して確認中。
