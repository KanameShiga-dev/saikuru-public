# 経験から正式なプロジェクトスキルへ

カードの「引き継ぎDBの履歴」から候補を開き、用途・適用条件・手順・必要な道具と権限・検証方法と結果・失敗時の対応を入力します。確認チェックを入れ「確認した版を登録して有効化」を押すと、同じプロジェクトの依頼・台帳相談で自動参照されます。

元の経験の原文をそのまま実行指示へ昇格させません。記入した正式版だけを参照します。疑わしい指示は既存の添付用注入検査で拒否し、認証情報の典型パターンと個人のユーザーパスも拒否します。完全なDLPではないため、個人情報・案件固有の秘密の除去は確認者の確認が必要です。

正式化は手順が検証済みであることの自動証明ではありません。ログイン未実装のため確認者の本人識別もできません。操作日時と対象依頼をイベントに記録します。

## 自動参照と版管理

用途・適用条件と依頼文の語が一致する有効な版を最大5件参照します。意味検索ではなく文字の一致であり、表現によっては候補を選べません。元の経験が矛盾・変更・参照対象外となった場合、正式版の自動参照は保留します。画面に「元の経験の再確認待ち」と表示します。

「正式化したスキルと過去の版」で利用停止・旧版の有効化ができます。同じ名前の利用版は1つです。新しい版は過去版を上書きせず保存します。旧版に戻しても元の経験が失効していれば自動参照されません。

CLIのスキルディレクトリや共通ハーネスへインストールしません。確認した手順を統括のプロジェクト文脈に渡す方式です。既存の権限、承認、利用者の今回の指示が優先します。停止しても実行中のセッションに渡した指示は取り消せないため、必要ならその依頼を中止してください。

## スキル一覧・ダウンロード・別プロジェクトへの適用

各画面の「スキル一覧」（`/skills`）から有効版を確認し、正式版のSKILL.mdをダウンロードできます。経験の原文・依頼ID・元環境のパスはダウンロードへ含めません。ただし正式版に記入した文章の秘密や案件情報が自動で全て除去されるわけではありません。配布前に内容を確認してください。

台帳の適用先を選び、条件と情報共有を確認して「選択したプロジェクトで使用する」を押します。適用先はAI作業対象の登録が必要です。元の版を参照する適用記録を保存し、コピー・CLIインストールは行いません。適用先でも依頼文の語と用途・条件が合う場合だけ自動参照します。元の経験が保留になれば共有先でも参照されません。元プロジェクトで新しい版を作っても適用先は選んだ旧版を保持します。

適用先の作業カードでも利用停止できます。同一スキルでも停止状態はプロジェクトごとです。一覧は有効化された適用先ごとに表示します。停止した版や過去版はカード側の履歴に残ります。ログイン・企業内の利用者別権限管理はまだなく、同じ統括画面へアクセスできる利用者間での共有です。

引き継ぎDBに `skill_versions`（不変の版）と `skill_active`（利用する版と状態）を追加します。DBのローカルバックアップとソースは `data/backups/skill-release-20261006/` に保存します。復旧はソースを戻して再起動します。追加テーブルは残しても旧ソースから利用されません。DB全体の巻き戻しは新しい履歴を失うため避けてください。

PythonとJavaScriptの構文確認を実施。実際の候補登録・停止・旧版復帰・モデルによる利用の一巡確認は未実施です。機能確認の未実施と、ソースの公開は別の確認事項です。
