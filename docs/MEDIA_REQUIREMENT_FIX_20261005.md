# 動画要件の欠落と回答時のファイル選択

## 原因

旧完了判定は指定拡張子・出力ハッシュ・ナレーション有無を確認していましたが、依頼の必須実画面と出力内容を照合していませんでした。生成ツールは文字スライドしか扱えず、モデルが素材未使用を確認記録に書いても、制作終了からレビューへ進めました。

今回の依頼は「匿名化した画面素材を中心」と明記していました。旧32の確認記録は3画面を本編未使用と明記しており、要件を満たしていません。最新DBではレビュー自体は終了し依頼がblockedでした。スクリーンショットの実行中表示だけでは現在状態を確定できません。

## 修正

- 実画面・操作動画・撮影素材等の要求から必須sceneを抽出し、計画にasset_pathを用いた本編統合工程を要求します。
- generate_mediaは許可された保存先内のPNG/JPEG/MP4を章へ取り込みます。素材は一時領域へコピーして固定し、出力記録に素材パス・SHA256・scene・章番号を保存します。外部URL・範囲外のパス・100MB超の素材は拒否します。
- 完了判定は必須sceneの網羅と素材ハッシュを確認します。制作担当がdoneを返した時点にも判定し、不足ならレビュー前にblockedにします。
- 質問への回答画面に標準ファイル選択を追加。ファイルを求める質問では添付欄を展開します。既存の添付検査を通したIDだけを、回答した依頼へ追加します。
- ファイル選択の対象形式・4件/15MB制限・プロンプトインジェクション検査は既存規則を維持します。動画ファイルの一般アップロードは今回追加していません。制作ツールのMP4素材指定は承認済み保存先にある素材のみです。

## 限界

素材の使用・同一性は自動確認しますが、sceneラベルと映像の意味的な一致、全編の発音・可読性・最終承認は人の確認が必要です。要件の自然言語抽出は上記表現に限られ、全種類の成果物条件を構造化したものではありません。明示的なdocument_media_requirements.required_scenesも完了判定で使用できます。

実行中タスク0・相談busy 0を確認して8790を正常再起動。配信app.jsと編集版の一致、Python/JSの構文を確認。実ブラウザーで回答して担当を再開する確認は未実施。稼働中の既存依頼・承認・DBを書き換えていません。新しいコードは再起動で反映済みです。公開・pushはしていません。

変更対象はteam_document_capabilities.py、document_tools.py、document_media_worker.py、team_engine.py、server.py、web/app.js。旧動画と撮影素材は維持。今回の統合版は資料保存先の統合版v3に別名で出力します。
