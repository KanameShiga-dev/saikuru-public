# 文脈削減の品質保護（2026-10-11）

## 修正

- 指示の行・文単位の重複除去を廃止。元の指示、空白、改行、コード、表、対象ごとの繰り返し条件を保持する。
- 補足の追加は、直前の補足と完全に同じ内容を再送した場合だけ省略する。途中で別の補足があれば同じ文章も再追加する。過去の方針へ戻す操作を妨げない。
- context_budget.mode=onでも、選択候補が経験の省略・並べ替え・スキルの要約を行う場合、選択前の再利用文脈を保持する。文字数上限を超えても品質保護を優先する。
- quality_fallbackと候補文字数を記録。ON時のchars_afterとexperience_droppedは実際に適用した値。候補による減少はcandidate_*に分離する。shadowは従来どおり候補だけの計測。
- DB、承認・安全条件、経験の元記録は変更しない。

## 検証

実行: `python -X utf8 -m unittest test_context_quality test_phase2 test_skill_match test_skill_read_fix test_review_checklist test_review_status test_document_goal test_document_relax test_usage_metrics -v`

55件合格（失敗0、エラー0、スキップ0）。新規12件は、繰り返すコード行・表・対象別指示・空白・直前補足の再送・方針の復帰・履歴・隔離DBでのEngine起動・長い経験の例外条件・キーワード不一致・Skillの検証手順・A〜Dの境界を含む。外部AI、ネットワーク、実業務DBは使用しない。ログはdata/measurement-20261011/recheck_context_quality.log、ソースハッシュ付き集計は同名.json。HTMLのJavaScript構文確認も合格。

文脈保護の検証は、担当へ渡すJSONがOFFとONで同一であることを照合する。モデルが経験を理解し適切に成果物へ適用することの評価とは別である。

## 運用と残る制限

通常設定のshadowは変更しない。起動中サービスのプロセスには再起動後に反映される。本変更では既存作業を中断しない。

過去の重複除去で既に失われた指示は自動復元しない。元の履歴と最新の利用者判断を確認して復旧する必要がある。

経験の事前選択（最大12件）や自動スキル候補（最大5件）は既存仕様として残る。本修正はその後の予算による追加欠落を防ぐもので、検索の網羅性を保証しない。
