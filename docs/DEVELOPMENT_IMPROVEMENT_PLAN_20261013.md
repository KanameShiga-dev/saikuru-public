# 開発ツール改善計画と受入条件（2026-10-13）

対象はWindows上の采来を監督して使う本人。目的は過去の判断を探せること、成果受領までの人の負担とレビュー効果を測れること、失敗後に安全に再開できること。

## 実装範囲

|順|変更|完了条件|
|---|---|---|
|1|過去の終了案件の検索、ページ送り、読み取り専用の詳細|該当なし・通信失敗・再試行を表示。目的・担当結果・承認履歴を再表示。閲覧で再実行しない|
|2|依頼別の本人/代理の累計実作業時間、承認・差し戻し・再試行の集計|未測定と0を分離。訂正履歴・同時更新検出。受領は既存の判断経路を維持|
|3|既知欠陥を含む架空在庫集計の評価セットと採点器|見逃し・誤指摘・重複を分離。未完了を0件合格にしない。正解はAI作業フォルダの外|
|4|取消・再起動・再試行・バックアップの隔離検証と運用追記|模擬ワーカーの取消通知、承認失効、明示再試行、DB復元可能性を確認。実CLIと区別|

機密・個人情報、通常DBの架空案件追加、Gemini利用、OS/ネットワーク設定変更、公開・Pushは対象外。新規依存パッケージ不要。

## 代表開発案件の評価手順

1. 新規の隔離フォルダに架空在庫集計を準備する。実案件・設定・過去会話をコピーしない。
2. 依頼は「CSVのitem,quantityを読み、同名を合算し、しきい値以下を名前順に表示するPython CLIを作る。負数・不正整数・不足列をエラーにし、入力ファイルを変更しない。空入力、重複、境界、日本語名のテストと短い操作説明も用意する」。単一関数修正より広い、入力処理・集計・CLI・説明の案件として扱う。
3. 采来の通常経路・通常レビュー・セキュリティレビューを使用する。実AIの送信内容は架空コード・依頼・実行結果だけ。使用モデル・推論設定・采来の版・総トークン上限・停止余裕を実行前に固定する。上限未承認なら開始しない。Geminiを使わない。
4. 実利用者が準備・操作・確認・修正・復旧に使った時間を別に計測する。待ち時間は含めない。ボードの依頼選択→「評価記録」で累計分数を保存。記録者を明示し、未測定なら空欄を維持する。
5. 独立確認：境界以下を含む、重複を合算、負数/不正整数/不足列を拒否、空入力、日本語名、入力不変、CLI終了コード、説明どおりの操作。結果に欠陥があれば差し戻し、同じ条件で修正を確認する。
6. 実利用者本人が成果画面で受領または条件付き受領を判断する。代理実行では本人の受領を完了扱いにしない。未確認項目への証拠追加と再受領も確認する。
7. 本人の累計時間、承認/拒否件数、利用者差し戻し、要修正レビュー報告、再試行を併記する。報告履歴に残っていない過去のレビューは集計できない。DBの受領状態だけで本人の確認を証明しない。

トークン削減は同じ元依頼・担当・モデル・設定・版・修正回の個別タスクの初回入力で比較する。対応しないタスク・失敗・unknownは別記。全工程の消費は予算管理。単一案件の成功を普遍的な品質・効率効果としない。

## レビュー能力評価

`eval/development_readiness/evaluate.py prepare <新規フォルダ>` は架空コードと依頼だけを生成する。AIやCLIを起動しない。正解は `cases.json` に保管し、モデルに渡さない。評価フォルダだけを対象に、固定したレビュー設定で変更禁止のレビューを行う。

本人または評価担当が各指摘を、具体的な再現例と仕様で照合する。既知のD1〜D3へ対応付けられない指摘は直ちに誤指摘とせず、正解表に未知の欠陥がないか確認する。正解表が不足していたら採点を止め、版を更新して別試行にする。

採点入力は次の形式。指摘本文・個人名・機密は保存しない。`defect_id:null` は人が誤指摘と確認したもの。重複指摘は検出数に加算しない。

```json
{"case_id":"synthetic-stock-v1","completed":true,"adjudicator":"human","findings":[{"finding_id":1,"defect_id":"D1"},{"finding_id":2,"defect_id":null}]}
```

`python -X utf8 eval/development_readiness/evaluate.py score <判定JSON>` で検出数、見逃した欠陥ID、誤指摘数、重複、再現率、適合率を出す。指摘なしの適合率は未定義。モデルの文章をキーワードで自動合否にしない。通常レビューとセキュリティレビューは目的を分けて扱い、この集計ロジックの3欠陥だけでセキュリティ能力を評価しない。

## 完了判定の境界

ローカル実装・合成検証と、実AIの結果・実利用者の受領は別の完了条件。実AI予算、本人の作業・受領結果、実CLIの強制終了時のプロセス回収が未確認なら明記する。OS隔離は管理部門相談結果待ち。

採点者がAI補助者の場合は adjudicator を assistant にして、本人採点と区別する。
