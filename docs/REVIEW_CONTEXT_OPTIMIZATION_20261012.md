# レビュー文脈の重複削減：隔離試作（2026-10-12）

状態：評価環境限定の実装と4件サンプル実AI比較を完了。利用者指定の主指標は同じ指示を持つ個別レビューの初回入力トークン削減率。観測された1.5〜3.9%を利用者は有効と判断。通常サービスの設定は `off` のままで、導入は未実施。

## 測定

過去の架空評価で成功したレビュー21回を、`eval/routing_comparison/inspect_review_context.py --summary` で読み取り専用集計した。ユーザー向け指示の合計247,297文字のうち、レビュー担当自身の指示と引き継ぎDBの最新版が**完全一致**して重複した本文は15,841文字（6.4%）。各レビューでは651文字または868文字である。引き継ぎ文脈全体は99,252文字。実測されたプロバイダの入力とキャッシュ読み取りは574,035トークン、出力は18,154トークン。ただしレビュー中の道具利用を含むため、文字数からトークン節約量を推定しない。

## 試作

`team_review_context.py` は、引き継ぎ側の当該担当レコードの `instruction` が現在の担当指示と完全一致する場合だけ、そのフィールドを省く。レコードのtitle・role・attempt、他担当の指示と報告、利用者判断、現在の事実、未確認事項、証拠、安全規則は残す。一致しない場合は省かない。

`review_context_mode` は `off`（既定）、`shadow`（候補文字数だけ記録）、`on`（重複を除去）を持つ。`shadow` と `on` は隔離評価の設定と、評価モード付き案件が評価ルート内にあることの両方を要求する。通常案件では設定を誤って有効にしても `off` になる。記録するのはmodeと文字数だけで本文は記録しない。`run_pair.py` は試行ごとのmodeをマニフェストに残し、modeを変える試行には新しい明示的な予算値を要求する。

## 比較の判定

構造比較では、`off` と `shadow` の引き継ぎ内容は同一。`on` は完全一致した指示本文以外を保持する。隔離の単体・経路テスト17件が成功した。これはAIのレビュー品質やトークン削減を示さない。

実AI比較はその後、利用者が新たに承認した120万トークン枠で開発・資料作成を各 `off`／`on` で1件ずつ実施した。詳細は [4件サンプル比較](REVIEW_CONTEXT_FOUR_SAMPLES_20261012.md)。同じ元指示・担当・モデル・修正回の個別レビューの初回入力では1.5〜3.9%の削減を観測した。全試行1,034,690トークンは予算の副指標として残す。資料は採点器の誤判定で追加修正を生じ、資料2件は条件付き受領。課題8の旧100万枠とは別計上する。

この重複はプロンプトの一部に過ぎない。個別レビューの小規模サンプルでは削減を観測したが、一般化や差し戻しとの因果関係は未確認。評価用の切替は既定 `off` のまま保持し、通常サービスへの導入はまだ行っていない。

変更差分だけを強制的に渡す次段階は保留する。評価案件にはGit管理されていないプロジェクトもあり、現行の変更ファイル走査は更新時刻による候補抽出で、正確な差分やレビュー範囲の証明ではない。差分を作るには、着手前後のスナップショット、ファイル範囲、機密情報の除去と出典を設計してから、全件の確認可能性を検証する必要がある。根拠のない「変更なし」や省略したファイルをレビュー担当に示さない。
