# 担当の「失敗」の表示と代わりの方法（2026-10-07）

## 背景
働き方の説明資料の依頼（2026-10-07）で、読み取り専用の調査担当に、コマンドが必要な事前確認が割り当てられた。担当は3回試しても実行できず、最後に「できない項目を残して先へ進む」と報告したが、先へ進む範囲は利用者が決める決まりのため、采来が受け付けずに止まった。
作業ボードには「引き継ぎ範囲の登録が必要です」という内部の言い方しか出ず、失敗したこと、原因、どうすればよいかが分からなかった。

## 用語
- 判断待ち（blocked）：担当が質問を出し、人の回答を待っている。
- 失敗（failed）：担当が決められた回数で工程を終えられなかった、または担当の報告を采来が受け付けられなかった。そこで止まる。

## 変更（`web/app.js` の `failureDiagnosis`・`failureCard`、`web/style.css`）
失敗した担当のカードの一番上に、赤い枠の欄を出す。
1. 「この担当は失敗しました（試行 N回で停止）」とはっきり書く。
2. 何が起きたかを平易に書く。判定の順は次のとおり。
   - 利用枠・ログインの失効（既存の判定 `stopReason` を使う）
   - 必要な道具（コマンドの実行）が無い。担当の報告の文から判定する。読み取り専用の役割であることを示し、開発の依頼なら「資料作成」で出し直す方法を案内する
   - 「できない項目を残して先へ進む」報告を受け付けられなかった
   - Python の起動失敗
   - AIとの接続、または報告の形式の失敗
   - その他（記録された内容を示す）
3. 担当の最後の報告（要約・未検証）を示す。
4. 代わりの方法を、原因に合うものから番号付きで並べる。それぞれに、該当する操作の場所へ移動するボタンを付ける。
   - できない作業を、次の作成担当に移して再開する（待機中の作成担当があるときだけ）→「ボードから復旧する」
   - その作業を未実施として残し、先へ進める → 回答欄
   - 補足を書いて再試行する → 回答欄
   - 依頼を中止して出し直す（資料作成として）→ 中止ボタン
   - 担当・モデルを切り替える（利用枠やモデルの不調のとき。道具が足りないときは解消しないと明記）
   - 依頼全体を中止する

表示だけの変更で、操作は既存の仕組み（復旧・再試行・モデル切り替え・中止）を使う。変更前のファイルは `data/backups/failure-card-20261007/`。
