# 台帳からプロジェクトフォルダを移動する

1. 台帳で移動したいプロジェクトの詳細を開きます。
2. 「プロジェクトのフォルダを移動」に移動先の絶対パスを入力します。例：`C:\Projects\MyProject`。その親フォルダは既存で、MyProjectは未作成にします。
3. 「移動先とGitへの影響を確認」を押します。
4. 移動元・移動先・所属Git・追跡ファイル数・影響・移る台帳ノードを確認します。
5. アプリ、IDE、ビルド、同期を停止し、確認チェックを入れて実行します。

## Gitとの関係

- 親Git内の子フォルダも移動できます。親Gitには追跡ファイルの削除差分が残ります。親Gitのコミット履歴は移動先へ移りません。
- 自分の `.git` を持つプロジェクトは履歴とremoteを含めて移動します。
- 外部Git作業ツリーは `git worktree move` で管理情報も移動します。サブモジュールや、他の作業ツリーを管理するGit本体は対象外です。
- 移動先が別のGit内の場合は事前に表示します。コミット、push、GitHub公開設定、remoteの解除・変更は行いません。

## 台帳・参照・履歴

プロジェクトと登録済みの子ノードは、ID・管理項目・履歴を保持してパスを変更します。「元ソースのパス」の参照も変更します。移動履歴には元と先のパス、対象ノード、影響、状態、DBバックアップを保存します。

コード内の絶対パス、IDE、外部スクリプト、既存のAI依頼や引き継ぎ履歴、AI作業許可設定は自動変更しません。移動後の起動確認と作業対象設定が必要です。

## 制限と復旧

同じボリューム内のフォルダ名変更を使うため、ファイル、NTFS追加ストリーム、属性を保持します。移動先に上書きしません。リンク・ジャンクション、別ドライブ、稼働中のツール自身、未完了の依頼がある範囲は停止します。

台帳更新に失敗した場合は、元のフォルダ名への復帰を試みます。復帰できない場合やサービス停止時は復旧確認待ちとして記録し、関連するAI作業と追加の移動を止めます。履歴の移動元・移動先・台帳バックアップを照合し、フォルダを重ねて上書きしないでください。

正常に完了した移動を戻す場合は、同じ機能で元のパスへ移動します。元のパスは未使用である必要があります。途中停止の復旧は自動再実行しません。
