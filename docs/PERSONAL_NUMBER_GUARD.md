# 個人番号候補と担当IDの区別

個人番号の検出は、自由記述・モデルへの入力・添付の抽出文字・ツール出力・Web検索・公開前チェック・文書品質チェックで、共通の `team_dlp.has_personal_number` を使います。

32文字すべてが16進数で、少なくとも英字を1文字含み、前後に英数字・アンダースコアが続かない識別子は、内部の12桁だけを切り出しません。采来の担当IDで発生した誤検知への限定的な対処です。この形式は本人性・データの出所・安全性を証明せず、番号以外の検査も免除しません。IDとは別にある番号候補は引き続き検出します。

「テスト用」「架空」などの記載や `task_id` という項目名だけでは免除しません。通常のテスト文書には `<個人番号>` などのプレースホルダーを使ってください。ガード自身の単体テストでは、隔離した合成入力で番号候補の拒否を確認します。任意の12桁を外部へ送るためのテストモード・許可リストは追加しません。

独立した12桁、4桁ずつ空白・ハイフンで区切った番号は引き続き候補として扱います。チェックデジットが正しくても架空とは判定できず、不正でも入力ミスの可能性があるため、チェックデジット不一致を送信許可には使いません。入力確認と外部送信時の停止、文書品質上の警告という既存の各経路の扱いは維持します。

今回の変更は文字列の検査に限ります。画像の画素にある番号の検出精度を保証するものではありません。既に停止した担当は自動再開せず、画面で内容を確認してから再試行します。
