# 工程間の測定移管

承認済み質問 `git_hash_hook_denied_third_time` の選択 `defer_to_step2` を、調査担当から直後の待機中実装担当への移管として保存する。

- 起動時に旧版で保存済みの承認も登録する。承認ID単位で重複登録を防ぐ。
- HEAD、ステージ状態、変更一覧、SHA256の測定を、工程2の退避・編集前の必須作業に追加する。
- 調査担当の `handoff` は担当範囲の終了として扱う。検証の免除や依頼全体の完了ではない。
- 移管先が `done` で終了するまで、レビューによる依頼全体の完了を認めない。測定証拠の内容は後続レビューで確認する。
- 正本DBの `scope_transfers` と専用引き継ぎDBの `scope_transfer` に承認と移管先を保存する。

対象は上記の既知の構造化判断に限定。任意の文章を移管許可として解釈しない。

変更前ファイル: `data/backups/scope-transfer-20260928/`
変更前DB: `backup-20260928-152831-f75487.sqlite3` と `handoff-backup-20260928-152831-f75487.sqlite3`。
復旧時は作業を停止し、現状をバックアップしたうえで対応するファイルとDBを戻す。DBを戻すとその後の判断履歴も戻るため、通常はコードのみ戻して履歴を保持する。
