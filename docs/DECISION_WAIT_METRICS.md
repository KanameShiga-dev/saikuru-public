# 人の判断待ち時間の計測

2026-10-03 実装。履歴画面 `/history` と認証済み読み取りAPI `/api/decision-wait-stats?from=&to=`（UNIX秒）を使用します。

## 定義
- 平日9:00〜18:00、日本時間が初期値。`business_hours` の曜日・開始終了・固定UTCオフセット・休日一覧で設定します。設定の編集画面、祝日の自動判定、昼休み除外はありません。
- 依頼の blocked / failed / awaiting_approval / awaiting_acceptance と、工程の awaiting_approval を人の判断待ちとします。`failed` は実エンジンが利用者の再試行待ちに使用しているため、計画の列挙に補足しました。
- 同じ依頼の重なる区間・隣接区間は結合し、二重計上しません。区間開始時の承認種類、修正上限、失敗などを種類に保存します。途中の理由変更は区間を分割しません。
- 再起動などの interrupted はシステム停止として別集計し、人の判断待ち指標から除外します。成果受領・中止は工程側の未終了区間も終了します。
- 勤務時間内の中央値・90パーセンタイル（nearest rank）・最大値を表示します。期間指定時は区間をその範囲へ切り取ります。継続中はAPI取得時刻まで計上します。
- 導入前の依頼は「計測開始前」。承認記録から過去の近似値は作りません。400日以上の日付範囲は計算範囲外として合計から除き、欠けた区間があることを明示します。
- 計測値は期限、承認、担当の選択、再試行の条件に影響しません。

## 保存とAPI
`team.sqlite3` に transitions と metrics_meta を追加します。Store.put の同じロック・トランザクションで状態変化だけを記録します。本文や認証情報は複製せず、ID・状態・時刻・種類のみです。既存オブジェクトは移行しません。job/taskの重複を結合し、履歴APIの waits に追加します。

## 通知と台帳
常駐通知は別機能です。初期無効、設定は notifications.windows_enabled。勤務時間内に、判断待ち・成果確認・成果受領の件数のみWindowsへ送信します。時間外の未解決項目は次の勤務開始後にまとめて送信し、配信済みと解消済みをDBへ記録します。再起動後に配信済み通知は繰り返しません。初回導入時に過去の成果受領を再通知しません。
Windowsへのログインが必要です。OSが表示しない場合や失敗時は画面内の通知を使用してください。ブラウザー通知も勤務時間外は保留し、常駐通知有効時はPC通知を重複送信しません。音声は利用者が有効にした画面でのみ動きます。
外部通知（Teams等）は接続先・送信範囲が未指定のため追加していません。
台帳詳細は5つのタブで切り替え、分類編集を基本情報に集約しました。フォームを再生成せず入力を保持し、既存の保存・移動・削除の確認条件を維持します。

## 検証と制約
計算、重複排除、期限切れ→停止→再試行、システム停止、期間指定、認証、通知の保留・重複防止を自動検証。隔離サンプルで台帳タブと保存、判断から修正の再依頼、相談からボードへの連携、履歴を操作確認しました。
Windows通知ヘルパーはテスト送信で正常終了。端末上の実際の表示、音声、サインアウト後、スマホ実機、実モデルによる完了一巡は未確認です。
更新前の版へ戻す場合は、正常停止して公開Gitの変更コミットをrevertし、再起動してください。新しい作業記録を失わないよう、通常はDBを巻き戻しません。
