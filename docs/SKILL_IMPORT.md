# スキルの取り込み手順（2026-10-07）

外から持ってきたスキル（`SKILL.md` を含むフォルダ）を、采来（サイクル）のスキル一覧に取り込む手順。

## 決めたこと（利用者：2026-10-07）
- 置き場所は采来の中：受け取りは `skills\_inbox\<スキル名>\`、取り込み済みは `skills\<スキル名>\`。
- 同梱のスクリプトも使えるようにする（下の安全のための決めごとの範囲で）。
- 適用先のプロジェクトは、取り込むときに選ぶ。

## フォルダ
| 段階 | 場所 | 意味 |
|---|---|---|
| 受け取り | `<采来の設置フォルダ>\skills\_inbox\<スキル名>\` | ここに置く。まだ使われない。スクリプトも実行できない |
| 取り込み済み | `<采来の設置フォルダ>\skills\<スキル名>\` | 確認して取り込んだ版。`.saikuru-import.json` に各ファイルの指紋（SHA256）を記録 |
| 控え | `<采来の設置フォルダ>\data\backups\skills\<スキル名>-<日時>\` | 同じ名前で取り込み直したときの前の版 |
| デスクトップ（任意） | `%USERPROFILE%\.claude\skills\<スキル名>\` | 取り込み時に選ぶと、デスクトップアプリの Claude Code でも使える |

## 手順
1. **置く**：スキルのフォルダを `skills\_inbox\` に置く。フォルダ名はスキルの名前（英小文字・数字・ハイフン）にする。
   - 必須：`SKILL.md`。先頭に次の形で name と description を書く。
     ```
     ---
     name: csv-summary
     description: CSVファイルの集計表を作るときの手順（どんな依頼で使うかを書く）
     ---
     ```
   - 置けるファイル：文書（.md .txt）、スクリプト（.py .ps1 .sh .js .bat .cmd）、データ（.json .csv .html .png .pdf .docx など）。
   - 置けないファイル：.exe .dll .msi .vbs .lnk などの実行ファイル、隠しファイル、リンク。
2. **確認**：采来の「スキル一覧」画面を開く。「取り込み待ちのスキル」に、次のものが表示される。
   - SKILL.md の本文、ファイルの一覧（種類・大きさ・SHA256）、同梱スクリプトの一覧
   - 機械チェックの結果（認証情報、`C:\Users\…` などの個人のパス、AIへの指示の乗っ取りらしい文、ファイルの種類・数・大きさ）。指摘があると取り込めない。元のファイルを直してから「最新の状態に更新」を押す
3. **取り込む**：本文とスクリプトの中身を確認し、次を選んで「取り込む」を押す。
   - 使うプロジェクト（1つ以上）
   - デスクトップでも使うか
   - 確認のチェック
4. **使う**：取り込んだスキルは「有効化したスキル」に表示される。選んだプロジェクトの依頼で、依頼文とスキルの説明（description）が合うと、手順が担当に渡る。
   - 渡る内容：本文（先頭約2600文字）と、全文のある場所
   - 担当は、そのスキルのフォルダの中を読める
5. **別のプロジェクトでも使う**：「有効化したスキル」で適用先を選び、「選択したプロジェクトで使用する」を押す。
6. **更新する**：新しい版を同じ名前で `_inbox` に置き、もう一度取り込む。前の版は控えに移る。
7. **止める**：取り込み済みのフォルダの中身を変えると、そのスキルは自動で「保留」になり、担当に渡らず、スクリプトも実行できなくなる。完全にやめるときは、取り込み済みのフォルダを控えに移す。

## 同梱スクリプトの安全のための決めごと
- 実行できるのは、コマンドを使える開発の依頼の制作担当だけ。資料作成・計画・レビューの担当は実行できない。
- 実行できるのは、そのスキルを有効にしたプロジェクトの依頼のときだけ。
- コマンドに出てくるスキルのファイルは、すべて取り込み時の SHA256 と一致する必要がある。1文字でも変わっていれば拒否する。`_inbox` の中のファイルは実行できない。
- 照合できても、コマンド全体は通常の承認の流れに乗る。今の設定（`automatic_operations: true`）では自動承認されるので、取り込むときの確認が実質の関門になる。
- 実行の確認・拒否は `skill_script`、スキルの読み取りは `skill_read` として記録し、毎回のセキュリティレビューの操作記録にも入る。

## プロンプト注入の疑いがある場合

疑いを検出した文書は取り込めません。該当箇所は確認のため表示しますが、確認チェックで拒否を解除しません。元ファイルを修正して再検査してください。
`LICENSE`・`NOTICE`・`COPYING`・`AUTHORS` は拡張子がなくても文書として検査します。

## 適用先の解除とスキルの削除（2026-10-07 追加）
- 解除：スキル一覧でスキルを開き、「適用先プロジェクト」の各行の「解除」を押す。確認の画面のあと、そのプロジェクトの依頼ではスキルを担当に渡さなくなる（スクリプトも実行できなくなる）。ほかのプロジェクトはそのまま。もう一度使うときは「ほかのプロジェクトでも使う」から適用する。
- 削除：スキルを開き、赤い枠の「削除する」を押す。確認の画面のあと、すべての適用先から外れ、一覧から消える。
  - 取り込んだスキル：フォルダを `data/backups/skills/<名前>-deleted-<日時>` に移す（完全には消さない）。デスクトップ（`~/.claude/skills/<名前>`）の分も移すかは、チェックで選ぶ。
  - 経験から作ったスキル：一覧から消えるだけで、元の経験の記録は残る。
  - 引き継ぎDBには、過去の版を監査の記録として残す。
- API：`POST /api/skills/unassign`（version_id・project_id・confirmed）、`POST /api/skills/delete`（version_id・confirmed・remove_desktop）。操作はイベント `skill_unassigned`・`skill_deleted` に記録する。
- 戻すとき：控えのフォルダを `skills/_inbox/<名前>` に戻し、取り込みの手順をやり直す。
- 変更前のファイルは `data/backups/skill-delete-20261007/`。

## 2026-10-08 修正：担当がスキルを読めない問題

- **原因1**：Claude CLI は `--restricted` でファイルの道具を作業フォルダ（依頼のプロジェクト）に閉じ込める。采来のチェックは有効なスキルの読み取りを許可していたが、CLI 側で拒否されていた。
  → 依頼のプロジェクトで有効な取り込みスキルのフォルダを、CLI に `--add-dir` で渡すようにした（`team_engine.py` の `Context.skill_dirs`、`team_adapters.py`）。書き込みは従来どおり采来がプロジェクト外として拒否するので、実質は読み取りだけ。`_inbox` は渡さない。実機の CLI で、`--add-dir` なしは拒否・ありは読めることを確認。
- **原因2**：コマンドの中に「_inbox」という文字があるだけで「取り込み前のスキルの実行」と判定していた（例：スライドの本文に「_inbox → 確認 → 適用先」）。
  → `skills/_inbox/…` を指すパスがある場合だけ拒否するように変更（`script_check`）。
- **あわせて**：取り込んだスキルのフォルダへ書き込むコマンド（リダイレクト・削除・移動・コピー先・Set-Content 等）を拒否するようにした。読み取りと、取り込み時のままのスクリプト実行だけが可能。
