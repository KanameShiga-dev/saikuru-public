# プロジェクト履歴

最終更新：2026-10-03（UI改善・利用量表示を反映）。

共通ヘッダーの「プロジェクト履歴」タブから `/history` を開きます。
プロジェクト、依頼の入口、依頼名で絞り込み、依頼を選ぶと承認記録と作業イベントを確認できます。
資料作成の依頼は保存先と読み取り元の両方から検索できます。

- 台帳の相談記録に紐づく依頼は「台帳からの依頼」。本機能追加後の直接作成は「新規依頼」。入口が保存されていない過去の依頼は「入口未記録」。
- 横棒は担当工程の記録時刻を使用。待機、実行中、停止、確認待ちを区別します。個々の再試行の区間は現在の工程レコードだけでは復元できないため、詳細イベントも参照します。
- イベントは新しい順に200件ずつ追加表示。保持されている記録が対象で、削除済みの履歴や未記録の操作は復元しません。
- 依頼者・監視担当・確認者・承認者の本人確認は未実装。人の名前を推測せず未記録と表示します。AI担当と人の担当は別です。
- 読み取り専用画面です。AIの追加呼び出しやWebへの送信はありません。既存のローカル画面認証を使用し、承認操作は作業ボードで行います。
- ページの更新ボタンで最新の状態を取得します。リアルタイム自動更新はありません。
- チーム利用のログイン・人物役割・閲覧権限・個人ライセンスでの分散実行は今後の課題です。

## 現在の画面

- 左に依頼一覧、右に選択した依頼の詳細を表示します。初回は最新の依頼を選択します。旧画面のプロジェクトごとの折りたたみは現在の配置では使用しません。
- 名前は台帳の基本情報のプロジェクト名を使用し、未登録ならフォルダ名を表示します。同名でも対象パスで区別します。
- 工程数、最新試行の実行時間の合計、再試行回数、確認・承認件数を表示します。全試行の累計実行時間ではありません。
- 目盛り付きの横棒に状態名、担当AI、モデル、試行回数、開始・終了、実行時間を表示します。人の担当とは区別します。
- 承認と作業イベントを1本の時系列にまとめ、「確認・承認／工程の進行／再試行・停止／その他」で絞り込みます。イベントの分類は名前のパターンによるもので、未知の種類は「その他」です。

## トークン消費と利用枠

- 工程別・依頼合計で入力、キャッシュ読取、キャッシュ作成、出力を別表示します。再試行・修正・レビューを含む、保存されたCLI報告の取得済み分です。
- 最大31試行分の実行履歴が対象で、記録不足をゼロとしません。取得済み件数と試行回数を併記します。依頼前の台帳相談は合計に含みません。
- 入力とキャッシュの定義はCLIで異なるため、全項目を単純加算した総トークンや課金額は表示しません。
- 最新の利用枠残量・取得日時を表示します。機能追加後の実行では開始前と終了後に既存モニターの取得値を保存し、詳細に最新試行分を表示します。追加の照会は行いません。
- 前後が同じ取得時刻の場合は消費差を示しません。アカウント共通の利用枠には他の作業も影響するため、依頼単独の負担とは断定しません。古い値・取得失敗・未取得は明示します。

## 確認済みと未確認

構文、稼働版ページ・API応答、UI改善時の隔離サンプルでの依頼切り替え・絞り込みと本番の表示を確認しています。UI改善の詳しい根拠は `UI_REDESIGN_20261003.md` を参照してください。本番の手動操作、スマホ実機、PC通知・音声の鳴動、全試行の会計照合や個人別の費用集計は未確認です。

## 判断待ち時間・試行別利用量（2026-10-03）
履歴詳細と時系列に人の判断待ちを追加。勤務時間内・時間外・システム停止を分け、上部の集計で期間・種類別の中央値・90パーセンタイル・最大値を確認します。導入前は計測開始前。定義は DECISION_WAIT_METRICS.md。
利用量欄には試行別のサービス・モデル・状態・トークンを表示します。過去にモデルが保存されていない場合はモデル未記録。検索0件では詳細も空表示になり、検索前の依頼を残しません。
保存済みCLI利用量47試行（失敗9試行を含む）と独立集計を照合し不一致0件。生プロトコル全件の保存はないため、モデル提供側との完全な会計照合ではありません。
