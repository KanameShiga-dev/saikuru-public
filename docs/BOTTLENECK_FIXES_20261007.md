# 判断待ち・失敗のボトルネック対策（2026-10-07）

## 背景
2026-10-07 の采来の記録では、AIの担当の作業時間が約54分だったのに対し、人の判断待ちが約145分あった（質問への回答12回、受け入れ5回）。担当の割り当て違いによる失敗が3回、再試行が15回あった。利用者の指示で、次の4つの対策をすべて入れた。

## 1. 割り当て違いの失敗をなくす
- 計画の点検（新規 `team_plan_check.py`、`team_engine.py` の計画担当の結果処理）
  - 開発の依頼で、調査担当・レビュー担当（読み取り専用）にコマンドが必要な作業（版の確認、ハッシュの計算、テストの実行、python・pip・npm・git・Get-FileHash など）を割り当てた計画を見つける。資料作成の依頼では、どの担当にもコマンドを使う作業を割り当てない。
  - 「禁止」「しない」などを含む文は、実行の依頼として扱わない（例：「pip / npm によるインストールは禁止」）。
  - 見つけたら、理由と直し方を計画担当に伝えて、自動で作り直させる（最大2回。イベント `plan_check_repair`）。それでも残れば止めて、理由を表示する（`plan_check_failed`）。
  - 計画担当への指示に、担当ごとの道具（読み取り専用の役割など）を最初から示す。
- 入口の案内（`web/index.html`・`web/app.js`）：「依頼を追加」の依頼名・本文に PowerPoint・スライド・資料・PDF などの言葉があれば、「資料作成として台帳の相談から出すと資料用の道具が使える」と確認を出す。キャンセルで入力に戻る。

## 2. 質問の数を減らす
- 計画担当：判断への影響が小さい不明点（ファイル名、縦横比、枚数の幅の中の値、表現の細部など）は標準を決めて指示に書き、質問にしない。採用した標準は summary に列挙する。利用者が決めるべきこと（範囲・方針・公開・費用・安全・元の依頼との食い違い）だけを、計画の時点でまとめて質問する。
- 作業・調査・レビューの担当：決められる細部は標準で進め、採用した標準を報告に書く。止めて質問するのは利用者の判断が必要なときだけ。
- 相談の担当（`team_consultation.py`）：UNKNOWN に「標準案：〜」を併記する。利用者が決めるべきものは「要回答」と明記する。
- 「依頼を追加」の本文に記入例（目的・材料・完了の条件・決まっていない点は標準で）と「記入例を入れる」ボタンを追加した。

## 3. 質問に早く気づく
- 常駐PC通知（Windows の通知）を有効にした（`notifications.windows_enabled: true`、勤務時間内のみ）。作業ボードの設定と同じ API で変更し、テスト通知を送った。有効にした時点で、通知対象の未処理が16件あり、次の勤務時間内にまとめて1回通知される。

## 4. 受け入れの確認を速くする
- 成果物のページ画像（新規 `team_preview.py`、`server.py`、`web/app.js`、`web/style.css`）
  - 依頼が「成果の確認待ち」になると、成果物の PowerPoint・Word・PDF を自動でページごとの画像にする（最大40ページ）。PowerPoint は PowerPoint で、Word は Word で PDF にしてから、PDF は pypdfium2 で画像にする。
  - 対象：資料作成の依頼は生成記録の成果物。開発の依頼は、依頼の開始後に変更された PowerPoint・Word・PDF。
  - 画像にする前に、マクロ・外部リンク・埋め込みを含む Office ファイルを拒否する。利用者が開いていた PowerPoint は閉じない。
  - 「成果を確認して受け入れる」欄に、ファイルごとのページ画像の一覧を出す（押すと大きく開く）。作成中は5秒ごとに表示を更新する。
  - API：`GET /api/jobs/previews?id=<依頼ID>`（未作成なら作成を始める）、`GET /api/previews/image?job=&key=&page=`。画像は `data/previews/` に保存。
  - 確認：サンプル08の2つの PowerPoint（各5ページ）が采来の中で画像になり、一覧に表示された。Word（1ページ、約17秒）、PDF（3ページ、約0.5秒）も画像化できた。

## 5. 使い方の工夫（実装なし）
- 采来は2件まで同時に進められる（`max_parallel_projects: 2`）。朝のうちに複数の依頼を出しておくと、AIの作業と人の作業がさらに重なる。
