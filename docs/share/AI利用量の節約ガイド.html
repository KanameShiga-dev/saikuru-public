1原因：何がトークンを食っているか

影響が大きいと考えられる順に並べています。

#原因何が起きているか
1長い会話を続けているAIは1回やり取りするたびに、それまでの会話全体を読み直します。1つの会話で作業を続けるほど、1回あたりの消費が雪だるま式に増えます。
2どの作業にも高いモデル・高いエフォートを使っている上位のモデルや高いエフォートを、簡単な作業にまで使っています。作業に合ったモデルを選ぶだけで、消費が大きく下がります。
3毎回読み込まれる指示ファイルが大きいCLAUDE.md・AGENTS.md・copilot-instructions などは毎回の入力に入ります。数百行あると、すべてのやり取りにその分が上乗せされます。
4道具（MCP・拡張機能）をつなぎすぎているつないだ道具の説明文も、毎回の入力に入ります。使わない MCP サーバーも、つないであるだけで消費します。
5やり直し・差し戻し・読み直しが多い依頼があいまいだと、質問・作り直し・同じファイルの読み直しが増えます。失敗した分も、すべて消費に数えられます。
6大きなファイルや出力をまるごと読ませているログ全体、巨大な CSV、PDF をそのまま渡しています。テストやビルドの長い出力も同じです。
7AIに何でもさせている検索・置換・整形・テストの実行など、普通のコマンドで済む作業までAIにさせています。
8同時に何本も動かしている複数の会話やエージェントを並べて動かすと、同じ枠を同時に使い、すぐに上限に当たります。

2担当者が知っておくこと

  1. 消費はトークン量にほぼ比例する「送る量を減らす」ことが、そのまま「枠を増やす」ことになります。
  2. 1回の入力には、今回の依頼以外のものがたくさん入っている
    指示ファイル＋道具の説明＋これまでの会話＋今回の依頼
    今回の依頼文は、このうちのごく一部です。
  3. モデルごとに単価が違うCopilot はモデルごとにクレジットの倍率が違います。短い依頼1回の実測では、小さいモデルが約0.06、中位のモデルが約0.5、上位のモデルが約1〜1.4クレジットでした。Claude Code でも、上位のモデルほど速く枠を使います。
  4. 「会話を続けたほうが賢い」とは限らない作業の区切りで会話を新しくし、必要なことはファイル（引き継ぎメモ）に書いて渡すほうが、安くて安定します。
  5. 圧縮の工夫より「送らない・読ませない・やり直させない」文章を縮めたり画像にしたりする工夫の効果は小さく、送る量そのものを減らすほうが効きます。
  6. 失敗とやり直しも消費に入る依頼の質が、そのまま費用になります。最初に完了条件を書くだけでも、やり直しが減ります。

3環境の仕組みとして入れるもの

担当者の心がけに頼らず、最初からそうなっている状態を作ります。

仕組み中身ねらい
共通の指示ファイルを短くするAGENTS.md を正本にして入口だけを書き、詳しい資料は「必要なときだけ読む」と案内する。CLAUDE.md は @AGENTS.md の1行で読み込む。大きさの目安（Codex は合計32KiB、Claude は200行程度）を点検する。毎回の上乗せを減らす。どのAIも同じルールで動く
役割ごとの推奨モデルを決めて配る調査・定型の修正は安いモデル、設計・難しい不具合だけを上位のモデルにする。エフォートは low・medium を標準にする。単価を下げる（実測 −78%）
MCP・道具を絞った標準の設定プロジェクトごとに、使う MCP だけを有効にした設定ファイルを配る。道具の説明の上乗せを減らす
作業を区切って引き継ぐ型「計画 → 実装 → 確認」で会話を分け、引き継ぎメモ（HANDOFF.md）のひな形で受け渡す。長い会話の雪だるまを防ぐ
依頼の型（テンプレート）目的・範囲・変更しない所・完了条件・確認方法を書いてから頼む。計画は作業1〜6個まで、修正は最大2回など、回数の目安を決める。やり直し・差し戻しを減らす
読み込みの上限大きな出力は末尾だけ渡す。添付はテキストに抽出してから渡す。ファイルは必要な範囲だけ読ませる。まるごと読みを防ぐ
利用枠の見える化と切り替え残りが少なくなったら安いモデルへ切り替え、回復したら戻す。月末の枯渇を防ぐ
同時に動かす数の目安1人が同時に動かす会話・エージェントの数を決める。同時消費による上限到達を防ぐ

4担当者個人の習慣（今日からできること）

  • 作業が一区切りしたら新しい会話にする。続きはメモに書いて渡す。
  • 簡単な作業は安いモデルで行い、行き詰まったときだけ上位のモデルにする。
  • ログや大きなファイルは、必要な部分だけを渡す。
  • 検索・置換・テストの実行は自分でコマンドを打ち、AIには結果だけを見せる。
  • 依頼の最初に、完了条件と確認方法を書く。
  • 使っていない MCP・拡張機能は外す。

5進め方

  1. STEP 1
    2週間測る

    利用者別・モデル別の消費と、「足りなくなった場面」を集める。

  2. STEP 2
    環境の仕組みを配る

    共通の指示ファイル、推奨モデル表、MCP の標準設定、依頼と引き継ぎのひな形。

  3. STEP 3
    同じ人で前後を比べる

    消費の減り方と、成果の質が落ちていないかを確かめる。

  4. STEP 4
    それでも足りない人だけ枠を増やす

    理由が「仕事の量」だとわかってから判断する。

ポイント 枠を増やす判断は、使い方を直したあとの数字で行います。先に枠を増やすと、消費の膨らみがそのまま残ります。
数値は検証環境（1台）での実測にもとづく参考値です。製品の仕様や料金は変わることがあるため、最新の情報は各サービスの公式資料と管理画面で確認してください。
