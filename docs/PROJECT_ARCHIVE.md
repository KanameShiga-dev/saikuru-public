# プロジェクトのアーカイブ（Windows用）

## 操作

1. ボード上部の「プロジェクト台帳」を開き、対象プロジェクト名を押します。
2. 詳細の「アーカイブ対象を確認」を押します。対象の絶対パス、件数、容量、ZIP保存先が表示されます。
3. 対象のアプリ・IDE・ビルド・同期を止めます。処理中は他のツールで内容を変更しないでください。
4. 表示したフォルダの削除を確認して「アーカイブを実施して削除」を押します。
5. 詳細画面で進捗と結果を確認します。画面を閉じてもPC側で処理が続きます。

削除は各実行の確認画面で明示的に確定します。台帳登録や確認ボタンだけでは削除しません。
Computer Use・プロジェクトのプログラム・LLMは使いません。外部サービスへ送信しません。

## 格納先と記録

`C:\Projects\_project_archives\<アーカイブID>\project.zip`

同じ場所の `manifest.json` に各ファイルの相対パス・サイズ・更新時刻・モード・SHA-256を記録します。
ZIPの中は元フォルダ名を頂点とする構成です。空フォルダも含みます。
台帳DBの `archives` に実行履歴・工程・ZIPのSHA-256・照合記録のSHA-256・元の場所・退避先を記録します。
管理項目の履歴とDBバックアップも保持し、台帳行自体は削除しません。
再調査では保管フォルダと削除処理用の退避フォルダを新規プロジェクトとして登録しません。

Git履歴・未コミット・未追跡・生成物・プロジェクト内の設定等を含むフォルダ全体を保存します。
ZIPは暗号化しません。元データに秘密情報がある場合はZIPにも含まれるため、このPC内で管理してください。
ZIPはファイル内容の保存用です。WindowsのACL・所有者・全ファイル属性・ディレクトリ時刻・ハードリンク関係の完全再現を保証しません。
リンク・ジャンクション・暗号化ファイル・ディレクトリのNTFS追加ストリームは拒否します。ファイルの追加ストリームは専用のZIP領域と照合記録に保存します。追加ストリームの復元には restore_project_archive.py を使います。
NTFS追加ストリームの判定は [MicrosoftのFindFirstStreamW仕様](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-findfirststreamw) に基づきます。

## 削除までの確認

- 確認は15分有効で一度だけ使えるトークンに結び付けます。対象の再確認、件数・容量・メタ情報の一致、圧縮用の空き容量を確認します。
- ZIPを閉じて書き込みを確定し、全ファイルを読み戻してSHA-256を照合します。
- 圧縮後に元ファイルのメタ情報と内容を再照合します。変更があれば元フォルダを保持して止めます。
- 削除中はZIPの書き換えをWindowsハンドルで抑止します。元フォルダを同じ親フォルダの `_project_archive_pending_<ID>` に移し、内容をもう一度確認します。
- 各ファイルは書き込みを許可しないハンドルで開いてSHA-256を再確認し、そのハンドルで削除します。新たに追加されたファイルを巻き込む再帰削除はしません。
- 削除完了後だけ台帳を「アーカイブ済み」に更新します。

Windowsのハンドルによる削除は [FILE_DISPOSITION_INFO仕様](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_disposition_info) に基づきます。

稼働中のAgent Team・DBを含む場所、他の台帳プロジェクトを含むフォルダ、親Gitリポジトリの一部分、外部Git領域を使う作業ツリー・サブモジュール、未完了の実行・待機依頼がある対象は処理しません。
アーカイブ中の対象と重なる新規依頼・タスクの起動も止めます。OS全体の書き込みを隔離する仕組みではないため、他のアプリを止める確認も必要です。

## 中断・失敗したとき

ZIPの完成前に失敗した場合は元フォルダを削除しません。未完成ファイルは `.partial` として残ることがあります。
削除前の内容照合で失敗した場合は、可能なら退避フォルダを元の場所へ戻します。
削除を開始した後に失敗した場合は、照合済みZIPと残った退避フォルダを保持し「復旧が必要」と表示します。
サービス再起動では進行中の記録を「中断」に変更します。削除を自動再開しません。
ZIPのSHA-256が履歴に記録されているか、実物が一致するか確認してから復元してください。

## 復元

1. まず元の場所・退避フォルダ・ZIPを確認します。残ったファイルは上書きせず保全します。
2. 台帳のZIP SHA-256と実ファイルを照合します（PowerShellの `Get-FileHash -Algorithm SHA256 -LiteralPath '<ZIPの絶対パス>'`）。
3. ZIPを空の別フォルダへ展開します。`manifest.json` の全ファイルのSHA-256・件数・空フォルダを照合します。
4. 確認後、展開された元フォルダ名のフォルダを元の絶対パスへ戻します。元の場所が既にある場合は混ぜて上書きしません。
5. 台帳を再調査し、存在を確認して管理状況を更新します。必要なアクセス権・依存関係・起動方法を確認してから作業を再開します。

アーカイブの成功はプロジェクトの動作確認を意味しません。復元の操作は手動で行います。
実プロジェクトの圧縮・削除・展開復元、およびスマホ操作の検証は今回の機能追加では未実施です。

## 機能変更を戻す場合

変更前のコードは `data/backups/project-archive-20260929` に保管しています。
サービスを停止して変更前のファイルを戻すことで機能を外せます。アーカイブ済みプロジェクトのフォルダはコードを戻しても復元されません。
ZIP・照合記録・台帳DBは保全し、上記の復元手順で別に戻してください。

## 削除とGitHub整理・追加ストリームの復元

元フォルダを削除する前にGitHubの非公開化と接続解除を行います。[削除とGitHub整理の手順](PROJECT_DELETE.md)を確認してください。
