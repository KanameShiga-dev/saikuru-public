# 経験からスキル候補を作る

通常の依頼で蓄積した `experience:lesson:対象:条件` と `experience:decision:対象:条件` から、スキルの下書きを自動生成します。登録操作や追加の承認待ちは発生しません。

## 候補になる条件

- 出典があり、同じプロジェクト内で矛盾が解消されている経験。
- 人が確認した記録、または同じ内容が複数の依頼に蓄積された記録。
- preference（好み）を手順として自動変換しない。

複数のAI報告は検証済みの証拠ではありません。候補の画面には未検証と表示します。対象と条件が異なる経験を全社共通の規則にしません。

## 見る場所

作業ボードでカードを開き、「引き継ぎDBの履歴」→「経験から作成したスキル候補（未有効化）」を開きます。適用条件、経験、根拠、元の依頼、正式化前の確認項目を表示します。「SKILL.md候補を保存」で利用者のブラウザから保存できます。

候補は最初から正式な手順ではありません。経験を手順の素材として残し、必要な道具・具体的な手順・検証方法・失敗時の対応・機密情報除去を確認してから正式化します。自動インストール・実行・共有ハーネス変更は行いません。候補ファイルに案件固有の根拠が含まれる可能性があり、公開前の確認が必要です。

## 保存と版

既存の `handoff.sqlite3` に追加した `skill_candidates` テーブルへ保存します。内容ハッシュで重複生成を防ぎ、更新時には別の版を保持します。現在の経験が矛盾・変更された場合、古い候補は画面の候補一覧から除外します。過去版は監査用に残します。最大100件の経験から抽出、画面表示は30件です。

## 未確認事項と復旧

Python・JavaScript構文を確認。実際の経験の蓄積から候補表示・ダウンロードまでの利用者操作は未検証です。意味的な経験統合、LLMによる手順の追加生成、正式化・配布・失効の管理画面は今後の対象です。

バックアップは `data/backups/skill-candidates-20261006/`。ソースを戻して再起動すれば自動生成と表示を停止できます。追加テーブルは旧ソースで参照されず、既存の依頼・事実を変更しません。DB全体を戻すと新しい記録を失うため、通常の復旧では戻しません。
