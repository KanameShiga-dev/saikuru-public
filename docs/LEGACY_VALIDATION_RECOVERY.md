# 従来形式の依頼が検証指摘の上限で停止したとき

検証を担当した作業が `needs_changes` のまま自動修正上限に達すると、後続レビューを開始せず、依頼は停止します。担当作業が終了していても、依頼の完成・検証合格を意味しません。

作業ボードの「あなたの判断」と判断待ち通知に、最後の検証担当を表示します。「依頼の進み具合」を展開すると、停止理由・最後の検証報告と「停止理由・検証結果を確認して判断する」が表示されます。

担当の詳細では、次の操作を選べます。

- **範囲を指定して修正を依頼**：最後の検証指摘と最新成果を読み、修正範囲の入力・確認チェックを経て、追加の修正を1回依頼します。修正後は検証のやり直し、通常レビュー、必要なセキュリティレビューへ進みます。自動修正の上限は変更しません。
- **中止の確認へ**：確認画面で依頼の中止を確定します。作成済みファイルは自動削除しません。
- **保留して閉じる**：実行・承認せず、停止状態と判断待ち表示を保持します。

操作欄を開いただけでは再開しません。古い検証担当からの重複依頼、実行中・未処理の承認がある依頼、新形式の依頼は、この従来形式向けの追加修正経路では開始できません。検証の省略・強制受領の操作は追加しません。
