# P0実Provider試験の実行メモ

状態：準備のみ。実Provider呼出し、標準UIでの登録、サービス起動は未実施。

## 対象

- 隔離ソースは統合ブランチの確定版を使う。通常運用サービスとデータを使わない。
- 専用の新規プロジェクトには `SCOPE.md` だけを置く。完成済みPoCや商品データを先入れしない。
- 依頼は計画7.2の「約1,000件の架空商品をIDで検索できるWebシステム」を標準UIから登録する。
- プロジェクト、実行記録、生成成果物はこの試験専用とし、架空の商品データだけを用いる。

## 呼出し前に確定する条件

1. Claude担当UIを統合し、標準画面でG1受付、G2計画開始、G3計画承認、完成物確認まで進めることを合成経路で確認する。
2. 実Providerの種類とモデル、送信する依頼文・SCOPE・生成中のコード、外部送信範囲、利用枠の上限、試行の停止条件について、利用者の有効な承認を記録する。
3. 既存の安全ガード、G2/G3、保守権限、外部送信検査を有効なままにする。承認のない有償再試行をしない。
4. 実行前に未開始の専用ランタイムと空の成果領域を確認し、試験開始時点と選択したコード版を記録する。

## 実行と確認

1. 標準UIでプロジェクトを登録し、依頼を入力する。技術的な補足はSCOPEに限定し、製品の設計判断は采来に行わせる。
2. G2の一回限りの承認、計画の成果物・受入条件・作業対応、G3の承認を別々に記録する。
3. 采来に実装、テスト、必要な修正、通常・安全レビューを実施させる。担当者が裏で完成物を作らない。
4. 完成候補の現行ファイルとテスト実行証跡を確認し、ブラウザーで起動、既存ID、欠番ID、不正入力、約1,000件の件数を確認する。
5. 技術判断要求、ゴール逸脱、無断実行、ガード違反、復旧の結果、利用量を実測する。未観測は「不明」と記録する。
6. 利用者に稼働画面と未達項目を提示する。本人の正式受領を担当者が代行しない。

## 終了条件

完成物の起動・検索・確認に失敗した場合、または本人の受入が未完了の場合はREADYとしない。同じ原因でのAI再試行は止め、保存済み成果と再開先を記録する。公開・本番切替・pushはこの試験に含めない。
