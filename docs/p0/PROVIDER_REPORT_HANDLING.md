# 担当モデルの完了報告の扱い

## 共通の約束

全担当に、最終報告を指定のJSONスキーマに合うオブジェクトだけで返すよう依頼する。CLIがスキーマ指定を受け付ける場合は、その機能も併用する。受信後は采来が同じスキーマで検証し、必須項目の欠落や型の違いを成功として扱わない。モデル名やProvider名から報告内容を推測しない。

| 接続先 | 初回の形式指定 | 受信後の扱い |
|---|---|---|
| Codex | `outputSchema` と共通の依頼文 | 最終回答から完全なJSONを回収して検証 |
| Claude | `--json-schema` と共通の依頼文 | `structured_output` を優先し、使えない場合は最終回答から完全なJSONを回収して検証 |
| GitHub Copilot | スキーマ本文を含む共通の依頼文 | 完全なJSONを回収して検証。従来形式の依頼では形の修正を同じ会話で1回依頼 |
| Gemini | スキーマ本文を含む共通の依頼文 | 完全なJSONを回収して検証。従来形式の依頼では形の修正を同じモデルへ1回依頼 |

前置きやコードブロックに包まれたJSONも、必要な項目と型がすべて合う場合だけ回収する。余分なキーは失敗理由にしない。自由文から成功・検証結果・成果物を采来が補作することはしない。

形式が直せない場合は成果物と失敗理由を保持し、依頼を完了扱いにしない。P0の依頼では、Copilot・Geminiも自動の追加モデル呼び出しをせず、実行メモに従って利用者の判断を待つ。今回のコード変更は停止中のE1担当を再実行せず、実Providerでの4経路の確認も行っていない。
