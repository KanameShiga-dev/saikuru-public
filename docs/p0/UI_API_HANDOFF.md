# P0統合API画面確認の引き渡し

2026-10-18。隔離した `p0/integration` のソースを使う。通常運用の8790サービスとDBは使わない。

## 架空11状態を実API経由で表示する

統合ブランチのルートで次を実行する。

```powershell
python -X utf8 tests/ui/p0/api_fixture_server.py --port 0
```

表示された `http://127.0.0.1:<port>/` をブラウザーで開く。`/api/state` は実際の `App.state()`、`App.redact_state()`、`team_p0_contract.progress()` を通る。入力は `tests/fixtures/p0/state.json` の架空11状態で、Providerは無効、作業エンジンは停止、POSTはすべて405で拒否する。一時DBは終了時に削除される。終了は起動したターミナルで Ctrl+C。

このランタイムで確認できるのは標準画面の表示、状態分類、詳細への移動まで。依頼登録、承認送信、Provider実行、完成物の起動、正式受領はここでは確認できない。これらを通したL4確認は、L3統合後に別の隔離ランタイムで行う。

## Codex確認結果

- 11件の架空依頼が統合版の標準画面に表示された。
- 復旧中は「チームが作業中」、保守対応待ちと安全停止は「待機している作業」に表示された。これらは「あなたの判断」には入らなかった。
- 安全停止の詳細は標準画面で「いまの状況」と中止操作を表示した。
- 成果物確認待ちの詳細で、未確認の起動・操作条件と証拠入力欄を表示した。起動・操作の実施証拠ではない。
- ブラウザーのコンソールエラーは0件。最初の架空入力では `task.profile` 欠損で描画が止まったため、画面確認ランタイムに実APIのタスク形状を補う処理を追加した。

## 固定SHAテストの扱い

`tests/test_safe_start.py::test_s13_normal_path_unchanged` は4ファイルの古い固定SHAを比較し、共通ベース `161c684` の時点から不一致。P0実装の合否には用いず、既存テストの更新要否として別に扱う。SHAを現行値へ置換するだけで本来の安全境界を検証したとはみなさない。
