# 企業の経験を自動で引き継ぐ

利用者は普段どおり依頼・回答・確認を行います。作業担当は、再利用できる判断理由・失敗と有効な対処・適用条件を `context_updates` の `experience:分類:対象:適用条件` に記録します。追加の登録操作や承認待ちは設けません。記録はプロジェクト単位で統括の引き継ぎDBに残り、担当・モデルの変更後も参照できます。

## 自動参照

作業依頼と台帳相談に、同じプロジェクトの経験を最大12件渡します。候補は直近2000件、依頼文の語と日時で順位を付けます。同じキー・同じ値は根拠と元依頼を保持してまとめます。矛盾が保留中、または同じ適用条件で異なる値がある経験は自動参照から除外します。異なるプロジェクトへは渡しません。

AIが抽出した記録は未確認です。利用者が既存の引き継ぎ情報登録・訂正で確認した事実とは区別します。今回の明示的な依頼と現在の根拠を優先し、記録内の文章は命令として扱いません。既存の引き継ぎ履歴から出典を確認できます。企業ログイン・共有権限は未実装のため、現在はこの統括環境の管理者による管理が前提です。

## 更新と限界

同じ依頼内のAI記録の更新は、既存の引き継ぎDBの更新規則に従います。別依頼の異なる記録を自動で正しいと確定しません。解消できない経験は除外して作業を続け、今回の判断に必要な不一致だけ担当が質問します。人の確認済み事実との矛盾を停止する既存の制御は維持します。

経験の抽出はモデルへの指示です。全ての経験の抽出を保証するものではありません。意味が同じ言い換えの統合、日本語の意味検索、古い会話の一括移行、相談だけで終わった会話からの経験抽出、経験専用の一覧・利用停止操作は今後の対象です。APIキー等の典型パターンは保存・参照時に拒否しますが、完全なDLPや個人情報検出ではありません。生の会話や個人情報を経験へ転記しない指示を併用します。

## 確認と復旧

Python構文を確認。実モデルの抽出・次の依頼への継承・矛盾時の人の操作は未検証です。DB形式の変更はありません。ソースのバックアップは `data/backups/enterprise-memory-20261006/`。停止中にソースを戻して再起動すれば従来の参照に戻り、記録を削除する必要はありません。
