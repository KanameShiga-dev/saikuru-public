# Codexの通常編集の自動承認（2026-09-27）

## 原因と修正

読み取りの自動承認だけでは、Codexの `item/fileChange/requestApproval` は毎回停止していた。また承認パラメータ単体には変更対象がないため、画面にもファイル名や差分が出なかった。

`team_adapters.py` で `item/started` のfileChange内容を保持し、threadId・turnId・itemIdが一致する承認要求に渡す。変更内容が取れない場合は自動許可しない。CLI 0.157.0のローカル生成スキーマでpath、diff、kind.type、kind.move_pathを確認した。

`team_auto_edit.py` は、実装担当かつ依頼にauto_execute=trueがある場合だけ、対象プロジェクト内の通常ソース・文書の追加・更新を許可する。対象パスの実体、保護領域、形式、サイズ、更新前の存在、重複を確認し、全対象を確認後に変更前データとハッシュ付きmanifestを `data/file-backups/<task-id>/<unique-id>/` へ保存する。バックアップに失敗したら手動承認に戻す。

削除・移動・対象外・権限追加・不明な変更形式・実行時データ領域・Git内部・方針や認証ファイル・JSON/Excel/Unityシーン等は自動許可しない。許可拡張子は実装に明記。ファイル拡張子の範囲は技術的な境界であり、変更の仕様適合性は別担当レビューと利用者の完了確認が引き続き必要。
