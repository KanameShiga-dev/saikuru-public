# プロジェクト削除とGitHubの整理

台帳の詳細画面に「プロジェクトを削除」を追加しました。
フォルダを削除し、台帳には「削除済み」と実行履歴を残します。復旧用ZIPを保存・検証してから削除する方式です。

## 操作と実行順序

1. プロジェクト名を押し、詳細の削除ボタンを押します。
2. GitHub公開先を自動検出します。過去に公開したものが出ない場合、詳細の公開先欄にURLまたは `owner/repository` を1行1件で入力して確認し直します。
3. 確認画面の元フォルダ・GitHubリポジトリ・Git remote名・復旧用ZIPの場所を確認します。
4. アプリを停止し、フォルダ削除とGitHub変更のチェックを入れて実施します。
5. GitHubリポジトリを非公開に変更し、同じリポジトリIDについて非公開を再確認します。既に非公開なら状態を確認します。
6. 確認画面に載ったGitHubのGit remoteをこのプロジェクトから解除します。
7. 接続解除後のフォルダ全体をZIPへ保存し、通常ファイル・追加ストリームを全件照合してから元フォルダを削除します。

アーカイブ機能でも元フォルダを削除するため、同じGitHubの整理を行います。
GitHubのリポジトリ自体は削除しません。コミット・push・新規リポジトリ作成は行いません。
複数のGitHub接続先がある場合は全部を確認します。fetch URLとpush URLの両方を調べます。
GitHub以外のホスト、SSHの独自ホスト名、既に消されたGit remoteからは公開先を自動確定できません。公開先欄にgithub.comのURLで指定してください。

## 必要な状態

GitHubに公開先がある場合、GitHub CLI (`gh`) のログインと管理権限が必要です。
非公開化・確認・接続解除のどれかが失敗した場合、ローカルフォルダの削除は止めます。
公開フォーク・組織の公開設定・権限などによる制限は自動回避しません。
非公開化は外部の利用者からの閲覧を制限します。変更対象は実施前の画面に明示します。

公式仕様： [GitHubのリポジトリ更新API](https://docs.github.com/en/rest/repos/repos#update-a-repository)、[GitHub CLIのAPI操作](https://cli.github.com/manual/gh_api)。

## アーカイブボタンの修正

Windowsのダウンロード元情報 `Zone.Identifier` など、ファイルのNTFS追加ストリームを検出すると中止していた処理を修正しました。
追加ストリームはZIP内の専用領域と `manifest.json` に保存し、元フォルダ削除前にも照合します。
ディレクトリに付いた追加ストリーム・リンク・暗号化ファイルは現在も対象外です。
確認処理はバックグラウンドにし、進捗と停止理由をボタンのすぐ近くに表示します。

## 失敗時の状態と復旧

GitHubの非公開化や接続解除後に圧縮等が失敗しても、公開設定を自動的に公開へ戻しません。
履歴に非公開化の確認状況・解除したremote名・残ったフォルダ・ZIPの保存先を記録します。
部分的に解除されたremoteの再接続が必要なら、利用者が公開先と認証方式を確認してからGitの設定を戻します。
ZIPの中のGit接続は解除済みなので、復元してもGitHubへの接続が自動で復活することはありません。

追加ストリームも復元する場合は、既存フォルダを上書きしない復元ヘルパーを使ってください（このツールのフォルダで実行）。

```powershell
python -X utf8 restore_project_archive.py <履歴のアーカイブID> C:\Projects\<新しい復元先>
```

ZIPとmanifestのSHA-256、復元した通常ファイル・追加ストリームのSHA-256を照合します。
GitHubの公開設定・WindowsのACL・依存関係・動作確認は自動復元しません。
その他の制約・手動確認は [アーカイブ手順](PROJECT_ARCHIVE.md) を参照してください。

コード変更前は `data/backups/project-delete-20260929` に保管しています。
今回の実装時に、実プロジェクトの削除・GitHubの公開設定変更・接続解除は実行していません。
