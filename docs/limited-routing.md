# 判断プロバイダーの限定運用

依頼受付時のみ、短い単一目的の依頼をローカルOllamaで分類する。送信は分類ヒントの列挙値のみで、依頼本文・パス・ソースは送らない。分類はDBのjob.intake_classificationへ記録し、計画担当の参考情報として使用する。計画、レビュー、作業範囲、承認を省略しない。

複合・曖昧・接続失敗は通常の計画担当へ渡す。削除・公開・権限変更などは「人の確認が必要」と記録し、既存の承認フローを維持する。通常の開発工程では担当選択のOllama問い合わせを行わない。明示した評価用benchmark_routing_contextは既存経路を維持する。

操作テストでは、完了・上限・中止を固定処理し、3候補以下のページ移動のみローカル判断を使用する。複合検索・状態更新は通常モデルへ直接渡す。進捗なし2回、STOP、不正候補、通信失敗は通常モデルへ渡す。8操作・12判断上限、重複操作拒否、中止後の遅延結果拒否を維持する。通常モデルは画面でClaude/Codexを選択できる。

設定のprovider=disabledは受付と操作テストのローカル判断を停止する。他のprovider指定でもこの限定運用はローカルOllamaのみを使用し、有料APIへ送信しない。旧shadowは開発Agent選択の互換フィールドで、受付の分類記録をシャドーへ戻す設定ではない。

2026-10-02の実装後測定で、Claude接続情報とページ操作候補の不具合を修正した。隔離された制御クラスの比較12件、本体画面のページ移動2件、注入したローカル失敗から実Claudeへの引き継ぎ1件は達成。受付分類の期待一致は12/15で、レビュー3件は通常計画へ戻った。受付から計画・担当詳細までの一連のUI、Codex実通信、長期効果、変更後の中止・境界再試験は未検証。詳細はdocs/reports/limited-runtime-evaluation-report.html。以前の評価結果を今回の実装の動作保証として扱わない。

戻す場合はdata/backups/limited-routing-20261002-162340の対象ファイルを確認して復元し、本体を再起動する。DBの過去履歴は戻さず、追加分類フィールドは残せる。
