# プロジェクト台帳

作業ボード上部の「プロジェクト台帳」から、一覧検索・管理項目編集・再調査・手動登録・JSON出力・DBバックアップを行えます。
PC画面は http://127.0.0.1:8787/ledger 。スマホは既存の認証済み入口から同じ台帳を開けます。

## 正本と初期項目

- 正本：`data/project_ledger.sqlite3`（SQLite、標準ライブラリのみ）。
- 管理項目：名称、目的・利用者、分類、管理状況、管理担当、元ソースのパス、ビルド・起動方法、検証方法・証拠の保存場所、完了条件、次の作業・未確認事項、制約・注意点。
- 調査情報：絶対パス、技術構成、README表題、既定の関連資料のパス、Git管理の有無、所属する親Gitリポジトリ、ブランチ、HEAD、変更・ステージ・未追跡の件数、存在確認、調査日時。
- AI作業許可は既存のチーム設定から表示するだけです。台帳登録や編集で作業権限を追加しません。Computer Useは基本禁止の方針を表示します。
- 目的・検証方法・完了条件・完了状況は自動確定しません。空欄を埋める推測は行わず「未確認」「未評価」で始めます。

## 調査範囲

`C:\AI_Work` 以下、深さ4まで。直下の候補と、Claude / Codex / tools 内の候補を探します。
Gitや技術構成の目印を見つけたら内部探索を止めます。ただし miscProject と学習資料には複数の開発物があるため内部の候補も登録します。
資料のフォルダや複数プロジェクトの親フォルダも候補として残し、実プロジェクトの件数と混同しません。
生成物・依存関係・バックアップ・認証情報・記録用フォルダは探索しません。family は直下のメタ情報だけです。
リンク・ジャンクションを探索せず、プロジェクトのプログラムやビルド・テストは実行しません。
各候補のルートと固定の技術構成ファイルの存在、README冒頭12行以内の表題のみ確認します。
深い場所や除外された開発物は「パスを指定して登録」で追加できます。全ファイル・全開発物を網羅した保証はありません。

## 保存と復旧

管理項目と調査情報を分け、再調査しても手入力は維持します。フォルダが消えても台帳は削除しません。
複数画面での編集競合は保存を止め、再読み込みを求めます。
更新前のDBバックアップ `data/project-ledger-backup-*.sqlite3` と、編集前のレコード `revisions` を保持します。調査履歴は `scans` です。
JSON出力は画面から現在の情報をダウンロードします。CLIのscan/export時には `data/project-ledger.json` と `data/project-ledger.md` も更新します（保存時点の一覧）。

CLI（このツールのフォルダで実行）:

```powershell
python -X utf8 team_ledger.py scan
python -X utf8 team_ledger.py export
python -X utf8 team_ledger.py backup
```

DBを戻す場合はAgent Teamを停止し、現在のDBを別名で保全してからSQLiteのバックアップ機能で選択したバックアップを正本へ復元します。
稼働中のDBファイルを直接上書きしないでください。復元したデータは次回起動時に読み込まれます。
他プロジェクトのソース・DB・認証情報は変更しません。台帳の情報をAIサービスへ送信する機能はありません。
