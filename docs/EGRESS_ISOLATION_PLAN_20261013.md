# 作業中の外部送信をOS側で制限する計画（2026-10-13）

## 目的と現在地

采来の文字列検査は、実行されるスクリプト内部の通信、OCRで読めない画像、未登録の機密名を完全には検出できない。CLIとその子プロセスに対するOSまたはコンテナ側の通信制限は未導入。現時点で「情報が外部へ漏れない」とは保証しない。

## 実装前に確定すること

1. Codex・ClaudeのCLI本体と、各ツールが起動する子プロセスを分けて観測し、必要な通信先と通信の主体を記録する。実案件の内容や認証値は記録しない。
2. 専用の隔離実行環境を用意する。通常のWindowsユーザー環境や共有Python実行ファイル全体に対するファイアウォール変更は避ける。
3. 隔離環境内の任意のコマンドとその子プロセスは、外部ネットワークへ直接到達できない状態にする。モデルとの通信はホスト側の限定ブローカーで行い、ツール実行のネットワーク許可を引き継がせない。
4. プロジェクトの読み取りをブローカー経由にし、ファイル分類、対象範囲、送信内容を確認してからモデルへ渡す。分類できないファイルは送信しない。
5. Web検索・外部API・公開操作は別の明示的な許可経路だけを使用し、宛先と送信内容を表示して利用者の承認を得る。認証情報と制限データは承認があっても送らない。

## 隔離環境で必要な確認

- 通常の作業、モデル接続、ローカルのファイル編集ができる。
- 直接通信と、許可したローカルスクリプトからの間接通信が遮断される。
- DNS、プロキシ、MCP、CLIの自動更新、子プロセスを通じた迂回が遮断される。
- 誤って遮断した場合、隔離環境だけを停止・復元でき、既存の采来のDBとプロジェクトデータを保てる。
- ファイル・添付・画像の内容が分類できない場合は停止し、未確認を明示する。

## 導入境界

OS・ネットワークの設定変更や隔離基盤の導入は、この文書の作成だけでは実施しない。作業中の依頼がないこと、影響を受けるCLIと接続先、復旧手順を示したうえで、利用者の別途の明示的な承認を得てから隔離した環境で着手する。
