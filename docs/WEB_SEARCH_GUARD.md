# Web検索の許可範囲と検索前チェック（2026-10-06）

利用者の指示により、調査担当（researcher）と実装担当（builder）にWeb検索（WebSearch）を許可し、全担当の検索語を検索前にローカルで確認して、社内情報を含むものを止める仕組みを追加した。

## 許可範囲

| 担当 | WebSearch | ページ本文の取得（WebFetch） |
|---|---|---|
| 計画・レビュー・資料作成の各担当 | ○（従来から） | × |
| 調査・実装担当 | ○（今回追加） | × |

共通Agent定義ファイルは変更せず、`team_engine.py` の `prepare_agent` で researcher/builder の道具に WebSearch を足す。

## 検索前チェック（team_web_guard.py）

Claude の全ツール呼び出しは `approval_hook.py`（PreToolUse）→ `Engine.tool_request` を通る。その入口で WebSearch の検索語を `check_query` で確認し、該当すれば拒否する。判定はローカルの規則のみで、外部送信はしない。エラー時は拒否（フェイルクローズ）。

止める内容：
- 200文字超・複数行（資料やコードの貼り付け）
- 認証情報らしき文字列（秘密鍵、AWS/GitHub等のトークン、JWT、`password=` など）
- メールアドレス、電話番号、12桁の番号
- 社内IPアドレス（10/8、172.16/12、192.168/16）、社内ホスト名（.local .lan .corp .internal .intra 等）
- PC内・社内共有のパス（`C:\`、`\\server\`、`~/`、`/Users/` 等）
- このPCのユーザー名・コンピューター名・ドメイン名、対象プロジェクトのフォルダ名（`01-development` のような汎用名は除く）
- `data/websearch-policy.json` に登録した社内の固有名詞（`blocked_terms`）と社内ドメイン（`blocked_domains`）

記録：通した検索はイベント `websearch_allowed` に検索語を記録。止めた検索は `websearch_blocked` に理由と文字数だけを記録し、検索語そのものは残さない。拒否時は担当へ「一般的な技術用語で作り直す」よう返す。担当への指示文にも同じ注意を追加。

## 運用

- **`data/websearch-policy.json` に会社名・顧客名・製品やシステムのコード名・社内ドメインを登録すること。** 初期値は空。編集は即時反映（再起動不要）。
- 規則による判定のため、言い換えや一般名詞に紛れた固有情報は止められない。止めすぎ・漏れは運用で調整する。
- 実装担当は Bash を持つため、コマンド経由の通信は検索前チェックの対象外（操作の自動承認が有効な場合は特に注意）。
