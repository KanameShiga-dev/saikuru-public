# トークン削減の個別タスク比較（2026-10-12）

状態：利用者指定の現行計測方針。過去の受入1件あたり・依頼全体の集計値は履歴と予算管理に残すが、プロンプト文脈の削減率の主指標にはしない。

## 主指標

同じ元の依頼・担当・タスク指示・モデル・推論設定・采来の版・修正回を持つ個別タスクを対にし、**初回モデル呼び出しの入力トークン**を比較する。

`削減率 = (削減なしの初回入力 − 削減ありの初回入力) ÷ 削減なしの初回入力 × 100`

元のタスク指示は同じだが、最適化対象の文脈を省くため、モデルへ組み立てた全文プロンプトは両条件で異なる。プロンプト本文・指示文・ハッシュを集計出力に含めない。利用量が両側とも最終値で、初回入力が取得でき、試行回数も一致する場合だけ率を出す。取得できない場合は比較不能と表示し、0として扱わない。

レビューから差し戻された場合も、修正回が同じで元の指示が一致するレビュー同士を対にする。片側にしかない修正後レビューは比較不能として、発生回数と取得済み使用量を別記する。レビューの `done` と `needs_changes` の違い、独立採点、通常／条件付き受領は削減率の横に表示し、品質判断から切り離さない。

## 副指標

- 個別タスク全体の `input_total + output` とその差。
- 対応しない追加タスク、再試行、失敗、unknown/partial の件数と取得済み使用量。
- ゴールまでの全体使用量、受領状態、所要時間。全体使用量は予算管理に用い、個別タスクの削減率へ混ぜない。

今回の隔離評価は `eval/routing_comparison/compare_task_tokens.py <削減なしの試行フォルダ> <削減ありの試行フォルダ>` でDBから読み取り専用で再計算できる。結果と制約は [4件サンプル比較](REVIEW_CONTEXT_FOUR_SAMPLES_20261012.md) に記録した。Copilot CLIは別環境のため今回の対象外。
