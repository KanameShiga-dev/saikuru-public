# 采来 — サイクル —

Codex／Claude Codeとプロジェクトの作業状態・引き継ぎ・検証結果を管理する、Windows向けローカル開発運用基盤です。

最新ソースから作成した公開用スナップショットです。過去のGit履歴、個別環境の運用記録、DB、認証情報、操作画像は含めません。
采来で開発するプロジェクトには、ハーネス環境と最低限のセキュリティ設定（セキュリティ方針、アプリが守る要件、Claude Code の権限設定）を展開します。采来の外で開発・保守されても、同じ線がプロジェクトに残ります。詳細と限界は [基本思想](docs/SECURITY_BY_DEFAULT.md) の「作成するアプリへの展開」を参照してください。

## 起動

Python 3.11以上、利用するCodex／Claude Code CLI、必要に応じローカルOllamaを準備してください。CLIへのログインと共通Agent定義の導入が必要です。共通Agentが未導入の場合、開発担当の実行は停止します。

```powershell
python -X utf8 manage.py start
python -X utf8 manage.py status
python -X utf8 manage.py stop
```

実際のURLは起動結果を確認してください。調査ルートの既定値は一般例の `C:\AI_Work` です。導入先に合わせてteam_ledger.pyのROOTとteam_folders.pyのBASEを同じ境界に設定し、復元先の制約と画面の説明も合わせて確認してください。個別アプリのGUI自動承認は無効にしています。

## Ollamaのセットアップ

[公式Windows手順](https://docs.ollama.com/windows)から導入します。この実装のSystem One接続にはOllama 0.35以上と許可モデルを準備してください。

```powershell
ollama --version
ollama pull tev1:0.8b
ollama list
```

チーム設定の判断ProviderでローカルOllamaと導入済みモデルを選択し、保存して接続確認します。許可モデルはtev1:0.8b／tev1:4bです。モデルは自動ダウンロードしません。pullは通信量とディスク容量を使います。

Ollama Windowsアプリが起動していれば別のserveは不要です。未起動の場合は別のターミナルで `ollama serve` を実行します。GPUなしではCPUでの利用を前提に小さいモデルから始め、速度とメモリ負荷を確認してください。

接続先はHTTPループバックのみです。LANへの公開とAPIキー入力は不要です。decision.env.exampleは自動では読み込みません。接続失敗時は起動状態・モデル名・CLIとサーバーのバージョンを確認してください。遅延時はローカル判断を停止して通常モデルで継続できます。

## 通信切断後の手動再開

P0開発依頼で、AIサービスのDNS解決失敗・接続リセットなどが記録された場合は「通信回復後の再開待ち」と表示します。無線LANなどの接続を戻し、停止した担当の詳細で「接続と停止状態を確認」を押してください。保存済み成果と表示された操作結果を確認してチェックを入れ、「停止した担当から再開」を押すと、同じ担当・モデルで未完了部分を続けます。自動再実行・モデル切替・完了扱いはしません。

接続確認は固定のAIサービス接続先へのDNS・TLS疎通だけで、認証情報・依頼・ソースは送らず、モデルも呼びません。確認は最大8秒で打ち切り、再開時にも接続と対象の状態版を確認します。疎通成功はCLIのログイン・プロキシ経路・モデル応答の成功を保証しません。

成果・計画承認・検証証跡・停止前の操作記録は保持します。CLIの会話を復元するのではなく、停止した担当の新しい試行へ保存済み操作結果を渡します。成否不明・時間切れの操作、未処理の質問、安全上の停止、必要な保守確認やチェックポイント照合は解除しません。計画担当の再開には従来どおり新しいAI開始承認が必要です。既存のDNS失敗も起動時に表示を整理しますが、依頼は自動で再開しません。

## 運用上の境界と未確認事項

正式受領で止まった場合は、受領ボタン直下に拒否理由を表示します。「受領できない理由を確認」は正式受領と同じ検査だけを行い、依頼や承認を受領済みに変更しません。通信・応答待ちが時間切れになった場合も結果未確認のエラーを表示し、同じ受領操作を自動で再送しません。

Web成果は「ページを開く準備」から起動できます。プロジェクト内の既存の起動・停止スクリプトと空きポートを采来が選び、起動・停止を個別に許可した後でページを別タブに開きます。ポップアップがブロックされた場合は「反映済みのWebページを開く」リンクを使ってください。設定が一意に決まらない場合だけ詳細設定を使います。起動は画面の合格・正式受領とは別です。

条件別レビューの「利用者確認待ち」は、受入条件の原文を `pending_checks` に残し、`pending_check_details.source_excerpt` に同じ承認済み条件の全文を引用して対応付けます。`check` は具体的な画面確認手順でも構いません。説明文と条件文の違いだけで実装修正へ戻しません。原文・出典・担当・必須性・実施可能性の不足や、実際の不合格は引き続き拒否します。解消済みの通信障害は現在の保守待ちとして表示しません。

旧検査だけで拒否された保存済みの最新レビューは、認証済み画面操作の `/api/recovery/recheck-criteria`（`id`、`confirmed: true`）で再検査できます。未解決の指摘・安全停止・必要な保守確認・他の実行中作業があれば拒否し、元の報告を履歴に残します。再検査はAI再生成や修正上限の解除ではなく、未完了の後続レビューまたは利用者確認へ進める操作です。正式受領は行いません。

修正で登録済み成果物が変わった場合、最終レビューでは直前の修正担当が成功させた指定検証の証跡と全登録ファイルのハッシュが一致するときだけ、成果物の版を更新します。更新前後のハッシュと検証担当は履歴に残します。検証後の変更・証跡不足では更新しません。この版の不整合だけで停止した最新の保存済みレビューは `/api/recovery/recheck-artifacts`（`id`、`confirmed: true`）で同じ照合を行えます。画面確認・正式受領や実際のレビュー指摘は省略しません。

AIの報告だけで完了とは判断しません。削除・公開・外部送信・権限変更は作業範囲と承認を確認してください。CLIへ渡した作業内容は各提供サービスへ送信されます。ローカルDB・ZIP・ログは個人情報を含み得るため公開しないでください。

このスナップショットの新規PCへの導入と一連の実動作は未検証です。汎用的な速度・トークン削減効果を保証しません。ライセンスの許諾条件は未設定です。

## 参考ファイルの添付（2026-10-04）
新規依頼と台帳相談で画像・PDF・Office・テキスト／ソースを参考添付できます。送信時にローカルで抽出・OCRし、指示の偽装や検査不能なファイルを拒否します。文書は抽出文字、画像は正規化したPNGとして担当へ引き継ぎます。4ファイル・各5MB・合計15MBまで。既存の作業範囲と承認条件は維持します。

[対応形式・導入環境・拒否・保存・限界](docs/ATTACHMENT_SAFETY.md)、[初期画像実装の記録](docs/IMAGE_ATTACHMENTS.md)。専用Pythonの依存はrequirements-attachments.txt、OCRはWindows日本語・英語が必要です。個人環境のdata設定・添付・DBは公開対象外です。実ファイルのOCR、拒否・誤検知、AI送信の一巡は未確認です。検査通過は安全の保証ではありません。

## 指示ファイルの容量・不足警告（2026-10-04）
台帳にAGENTS.md系/CLAUDE.md系の不足警告とフィルタを追加。「どちらか不足」「両方なし」「AGENTS.md系なし」「CLAUDE.md系なし」「両方あり」「未確認」を既存の検索・分類と組み合わせます。台帳表示時にファイル名の存在を確認するため、旧台帳の再調査は不要です。自動生成・編集・作業停止は行いません。

容量・行数・階層合計候補も診断します。Codexの既定合計32 KiB、Claude Codeの推奨200行未満とCLAUDE.mdの4 MiB上限を区別し、采来独自の容量注意も明示します。未確認の範囲や実効設定を断定しません。[調査根拠・操作・コンバートによる作成・限界](docs/INSTRUCTION_SIZE.md)。実画面のフィルタ・警告操作、境界値、実際のAI読み込み範囲は未確認です。
